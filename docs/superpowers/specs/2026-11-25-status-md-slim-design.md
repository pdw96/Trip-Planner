# status.md 줄이기 (#108)

## 왜

새 세션은 매번 `docs/status.md` 를 읽는다(`CLAUDE.md` '작업 흐름'). 파일이 56,918 바이트로 커졌고 지나간 기록·남은 일·팁이 섞여, 읽는 비용이 들고 지금 필요한 정보가 묻힌다. 커진 원인은 "이슈가 끝나면 `status.md` 를 고친다" 규칙 아래 세션마다 표 한 줄 + 프로덕션 확인 + 남은 지적을 더해 온 것이다.

## 목표 / 목표 아님

- 목표: 남은 일은 GitHub 이슈로, 지나간 기록은 git·PR 에 맡기고, `status.md` 에는 지금 상태·다음 할 일·위치 안내·`알아 둘 것` 만 남긴다. 다시 쌓이지 않게 `CLAUDE.md` 갱신 규칙을 바꾼다.
- 목표 아님(사용자 결정, 2026-11-25): `알아 둘 것` 을 주제별 파일로 나누기, 결정 기록(ADR), 새 문서 종류.
- 실패로 볼 것: 이슈 목록이 길어져 "할 이슈 고르기"가 어려워지는 것, 남은 일이 옮기는 중에 사라지는 것.

## 방법 (고른 것: 1)

1. **PR 하나로 `status.md` 와 `CLAUDE.md` 를 함께 고친다** — 작업 흐름 규칙이 한 곳에 남는다. `CLAUDE.md` 는 위험 경로라 `human-approved` 가 필요하다. **골랐다.**
2. 규칙을 `status.md` 맨 위에 적는다 — 라벨은 필요 없지만 규칙이 두 파일로 흩어진다.
3. PR 을 둘로 나눈다 — 그 사이에 끝난 세션이 옛 규칙으로 다시 쌓는다. 바꾸는 줄이 적어 나눌 이유가 약하다.

**`docs/status.md` 새 모양**

- 머리: 기준 날짜, 갱신 규칙 한 줄(`CLAUDE.md` 를 가리킴).
- `## 다음 할 일`: 열린 이슈 안내(지금 내용 유지, 새 이슈 4개 반영).
- `## 찾는 곳`: 설계는 `docs/superpowers/specs/`(날짜-주제 이름), 이슈별 내용·남은 지적은 PR 본문, 남은 일은 위 이슈들.
- `## 알아 둘 것`: 지금 내용 그대로 + 옮겨 오는 것(아래).
- 지움: `## 끝나서 배포된 것` 표 전체, `## 남은 확인` 절 전체.

**옮기는 것**

- `다음 할 일` 아래 쿼리 구조 설명(`accessibleTrips`·`visibleToUser`) → `알아 둘 것` 의 "쿼리 구조" 항목(코드 규칙이지 할 일이 아니다).
- `남은 확인` 의 팁 → `알아 둘 것`: 브라우저 확인 팁(#90), 클라우드 `node_modules` 가 lock 보다 낡을 수 있음(#91), 액션은 SHA 로만(#80 정책, 'Dependabot' 항목에 합침), `human-gate` 가 Dependabot PR 마다 3번 도는 이유(#65).
- 지움: 끝난 프로덕션 확인 기록(#74·#67·#68·#71·#76·#65 첫 실행·#53·#91 확인·#88), "#89 배포 주의"(`알아 둘 것` 롤백 금지선과 같음).

**`CLAUDE.md` '이슈 → PR' 의 갱신 규칙**

지금: "이슈가 끝나면(PR 머지, 배포 확인) `docs/status.md` 를 고치고 사용자에게 새 세션을 권한다."

바꿀 뜻(문구는 구현 때 다듬는다):
- 이슈가 끝나면 `docs/status.md` 의 '다음 할 일' 을 고치고, 새로 알게 된 함정·도구 팁만 '알아 둘 것' 에 더한다. 끝난 기록은 적지 않는다(PR 과 git 이 기록).
- 고치지 않은 지적은 PR 본문 "남은 지적" 에 적고, '남은 지적 모음' 이슈에 PR 링크와 한 줄을 더한다.
- 사용자가 실제로 해 볼 확인은 '실제로 써 볼 것' 이슈에, 사용자 결정이 필요한 것은 새 이슈로.

`CLAUDE.md` 의 다른 `status.md` 언급(Dependabot ignore 기록, 롤백 금지선, '남은 확인' 의 "적용 안 된 마이그레이션")은 그 자리를 유지하거나 새 위치로 맞춘다. '남은 확인' 절이 사라지므로 "적용 안 된 마이그레이션" 은 `status.md` 머리 바로 아래 눈에 띄는 자리(있을 때만 생기는 `## 적용 안 된 마이그레이션`)로 옮긴다.

## 내가 정한 것 (확인해 주세요)

- 앞으로 생기는 남은 지적도 모음 이슈에 한 줄씩 더한다. PR 본문에만 두면 2번(모음 이슈)을 고른 이유인 "잊히지 않게"가 이번 한 번으로 끝나기 때문이다.
- "적용 안 된 마이그레이션" 은 `status.md` 의 있을 때만 생기는 절로 둔다(이슈로 하면 다음 `db:migrate` 를 하는 세션이 놓치기 쉽다).

## 구현에 맡기는 것

- 각 이슈 본문 문구, 남은 지적 중 "설계에서 받아들임" 판정(PR 본문 근거).
- `알아 둘 것` 에 옮겨 오는 항목의 자리와 합치는 방식.
- PR 본문: 맨 위 "사람 확인 필요"(`CLAUDE.md` 바뀜), 줄어든 바이트 수, `Closes #108`.
