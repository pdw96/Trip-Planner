# 여행 날짜 범위 달력 설계

- 날짜: 2026-11-18
- 이슈: pdw96/Trip-Planner#17
- 상태: 승인됨 (2026-11-18). "Claude 판단" 표시 항목도 이 승인에 포함된다.

## 1. 의도

여행 만들기·고치기의 날짜 입력을 숙소 예약 앱처럼 바꾼다. 사용자는 달력 하나에서 시작일과 끝일을 차례로 눌러 범위를 고른다. 지금은 브라우저 기본 날짜 칸 두 개를 쓰는데, 두 가지 문제가 있다.

- 연도가 6자리까지 입력된다. `max` 가 없어서 Chrome 이 275760 년까지 받는다.
- 다크 모드에서 달력 버튼이 거의 보이지 않는다.

새 달력이 기본 날짜 칸을 대신하므로 두 문제도 함께 사라진다.

사용자가 보여 준 참고 화면은 숙소 예약 앱의 "날짜, 인원 선택" 시트다. 여러 달이 세로로 이어지고, 체크인·체크아웃이 표시되며, 사이 날짜는 띠로 칠해진다. 위쪽에는 `12.31(목)~01.02(토) · 2박` 요약이 있고, 일요일·공휴일은 빨간 글씨이며, 아래에 "적용하기" 버튼이 있다.

## 2. 목표 / 비목표 / 반목표

**목표**
- 양식의 시작·끝 날짜 칸 두 개를 "여행 날짜" 칸 하나로 바꾼다. 칸에는 고른 범위 요약이 보이고, 누르면 달력이 열린다.
- 범위 달력에서 시작일과 끝일을 고른다. 사이 날짜는 띠로 칠하고, 위쪽에 요약을 보이며, "적용하기"로 양식에 넣는다.
- 일요일과 공휴일은 빨간 글씨로 보인다. 공휴일은 공공데이터포털 "한국천문연구원_특일 정보" API 에서 받는다.
- 휴대폰에서는 아래에서 올라오는 시트, 넓은 화면에서는 가운데 창으로 연다.

**비목표**
- 인원 선택 (참고 화면에는 있지만 이 앱의 여행에는 인원 필드가 없다).
- 달력 라이브러리 도입, 스키마 변경.
- 지난 날짜 선택 막기 (지난 여행 기록용으로 열어 둔다).

**반목표 (동작해도 실패로 본다)**
- 공휴일 API 가 실패하거나 키가 없을 때 달력이나 양식이 열리지 않는 것. 이때는 일요일만 빨갛게 보이면 된다.
- 서버 검증을 빼고 달력만 믿는 것. 클라이언트 값은 여전히 `parseTripInput` 이 검사한다.
- 공휴일 API 키가 클라이언트(브라우저)로 나가는 것.
- 고치기에서 기존 날짜가 달력 범위 밖이라 보이지 않거나 지워지는 것.
- 달력을 닫았다가 다시 열 때 적용하지 않은 선택이 남는 것. 취소하면 양식 값은 그대로 두고, 다시 열면 양식 값에서 시작한다.

## 3. 제약

- #11 설계(`docs/superpowers/specs/2026-11-18-trips-crud-design.md`)의 제약을 그대로 따른다. Next 16 `cacheComponents`, 세션은 Suspense 안, CLAUDE.md 규칙, 한국어 문구.
- 새 의존성 없음.
- 환경 변수 키 이름을 `.env.example` 에 더하므로 이 PR 은 위험 경로를 건드린다. `human-approved` 라벨이 필요하고, PR 본문 맨 위에 "사람 확인 필요"와 그 이유를 적는다.
- 공휴일 API 는 이 클라우드 세션에서 접속이 막혀 있고 키도 없다. API 호출은 응답 파싱 단위 시험으로 확인한다. 실제 공휴일 표시는 사용자가 Vercel 에 키를 넣고 머지한 뒤 프로덕션에서 확인한다(프리뷰 배포에는 로그인 설정이 없다).
- API 키는 쿼리 파라미터(`serviceKey`)로 보낸다. 서버에서만 호출하고, 응답 가운데 날짜 목록만 클라이언트로 넘긴다.
- 응답 형식 확인: 이 세션은 공식 명세도 실제 응답도 볼 수 없다. 개발 블로그 두 곳에서 확인한 형식을 기준으로 파서를 방어적으로 짜고, 아래 경우를 단위 시험한다. 배열/단일 객체 `item`, 빈 `items`, `locdate` 가 숫자/문자열인 경우, 오류 응답(XML 이나 `resultCode` ≠ `"00"`). 사용자가 실제 응답 예시를 주면 그것을 시험 데이터로 쓴다. 완료 기준은 §7.
- 브라우저 확인은 #11 과 같은 방식(프로덕션 DB 의 임시 테스트 계정)으로 하되, **이번 작업에서 따로 사용자 승인을 받는다**. 승인이 없으면 브라우저로 확인할 길이 없으므로 진행을 멈추고 묻는다.

## 4. 고려한 방식

| 방식 | 판단 |
|---|---|
| **A. 달력을 직접 만들기** | **선택 (사용자 결정).** 참고 화면 모양을 그대로 낼 수 있다. 날짜 계산은 순수 함수로 두고 단위 시험한다. 의존성 관리가 필요 없다. |
| B. react-day-picker + date-fns | 범위 선택과 키보드 접근성이 이미 있지만, 참고 화면을 내려면 스타일을 많이 덮어써야 하고 의존성이 두 개 늘어난다. |
| C. 기본 날짜 칸 고치기 (`max`, `color-scheme`) | 사용자가 원하는 범위 달력이 아니다. |

공휴일 출처도 세 가지를 견줬다. 코드에 목록을 직접 넣기, 공공데이터포털 API, 일요일만. **사용자가 API 를 골랐다.**

## 5. 정한 것

### 5.1 양식 (사용자 승인)

- 시작 날짜·끝 날짜 칸 두 개를 "여행 날짜" 칸 하나(버튼)로 바꾼다.
  - 값이 있으면 `12.31(목) ~ 01.02(토) · 2박 3일`, 없으면 "날짜를 선택해 주세요"가 보인다.
- 실제 제출 값은 숨은 입력 `startDate`·`endDate`(`YYYY-MM-DD`)로 보낸다. Server Action 과 `parseTripInput` 은 바꾸지 않는다.
- 서버 검증 오류(`errors.startDate`, `errors.endDate`)는 "여행 날짜" 칸 아래에 보인다. 둘 다 있으면 시작 날짜 오류를 먼저 보인다.

### 5.2 달력 동작 (사용자 승인)

```
┌─────────────────────────────┐
│        여행 날짜 선택     ✕  │
│ 📅 12.31(목)~01.02(토) · 2박 3일 │
│ 일  월  화  수  목  금  토    │  ← 일 은 빨간색
│          2026.12             │
│ 13  14  15  16  17  18  19   │
│ 27  28  29  30 [31]░░░░░░    │  ← 시작(체크인 대신 "시작")
│          2027.01             │
│               ░░░ 1 [2]      │  ← 끝, 1일은 공휴일 빨간색
│ 3   4   5 …                  │
│        [ 적용하기 ]           │
└─────────────────────────────┘
```

- 여러 달이 세로로 이어지고 스크롤된다. 요일 머리줄은 위에 고정한다.
- 처음 열 때: 양식에 날짜가 있으면 그 시작일이 있는 달, 없으면 이번 달(한국 날짜)로 스크롤한다.
- 고르기 규칙:
  - 아무것도 안 고른 상태에서 누르면 → 시작일
  - 시작일만 있을 때 같은 날이나 뒤의 날을 누르면 → 끝일 (같은 날이면 당일치기)
  - 시작일만 있을 때 앞의 날을 누르면 → 그 날이 새 시작일
  - 범위가 다 있을 때 누르면 → 그 날이 새 시작일, 끝일은 비움
- 지난 날짜도 고를 수 있다.
- 요약: `MM.DD(요일)~MM.DD(요일) · N박 N+1일`, 같은 날이면 `MM.DD(요일) · 당일치기`. 시작일만 있으면 `MM.DD(요일)~` 와 "끝 날짜를 골라 주세요". 연도가 다른 해(올해가 아닌 시작일, 시작과 다른 해의 끝일)는 `YYYY.MM.DD` 로 쓴다.
- 날짜 아래 작은 글씨로 "시작"·"끝"을 표시한다. 당일치기면 "당일"이다.
- "적용하기"는 시작일과 끝일이 다 있을 때만 누를 수 있다. 누르면 양식 값을 바꾸고 닫는다.
- 닫기(✕), Esc, 바깥 누르기는 아무것도 바꾸지 않고 닫는다.
- 일요일과 공휴일은 빨간 글씨, 토요일은 기본 색이다. 오늘은 굵게 표시한다.

### 5.3 달력 범위 (Claude 판단)

- 오늘 기준 12개월 전 달부터 24개월 뒤 달까지 보인다.
- 양식에 이미 날짜가 있으면, 그 날짜가 들어 있는 달까지 범위를 넓힌다(고치기에서 오래된 여행).
- 범위 안의 모든 달을 한 번에 그린다. 최대 수십 개 달이라 무한 스크롤은 쓰지 않는다.

### 5.4 공휴일 (사용자가 API 선택, 세부는 Claude 판단)

- 환경 변수: `DATA_GO_KR_SERVICE_KEY` (공공데이터포털 일반 인증키, Decoding 키). `.env.example` 에 이름과 설명만 적는다.
- 서버 전용 모듈(`import "server-only"`)에서 연도별로 `getRestDeInfo` 를 부른다.
  - 주소: `https://apis.data.go.kr/B090041/openapi/service/SpcdeInfoService/getRestDeInfo`
  - 파라미터: `serviceKey`, `solYear`, `_type=json`, 충분한 `numOfRows`. `solMonth` 가 필요하면 12번 부른다. 공식 명세에서 확인한다.
  - 결과: `YYYY-MM-DD` 문자열 배열.
- `use cache` + `cacheLife("days")` 로 연도별 결과를 하루 동안 재사용한다. 캐시 키는 연도뿐이다(키 값은 캐시 키에 넣지 않는다).
- 키가 없거나, 응답이 실패·형식 오류이거나, 시간 초과(5초)면 그 해는 빈 배열로 둔다. 서버 로그에 한 줄 남기고, 키 값은 로그에 쓰지 않는다.
- 응답 파싱은 순수 함수로 분리해 단위 시험한다. `items` 가 빈 문자열이거나, `item` 이 배열이 아니라 객체 하나인 경우도 처리한다. `isHoliday === "Y"` 인 `locdate`(예: `20270101`)만 쓴다.
- 양식은 공휴일을 기다리지 않는다 (Claude 판단). 만들기·고치기 페이지(Server Component)는 달력 범위 연도들의 공휴일 요청을 시작만 하고, 그 Promise(`Promise<string[]>`, 실패해도 빈 배열로 끝남)를 `TripForm` → 달력으로 넘긴다. 달력은 열릴 때 `use()` 로 읽고, 아직이면 작은 Suspense fallback 뒤에서 기다린다. 공휴일 응답이 느려도(캐시가 빈 첫 요청, 최대 5초) 양식은 바로 열린다.
- 서버 로그에는 실패 원인(응답 상태 코드, 응답 형식이 예상과 다름 등)을 한 줄 남긴다. 키 값과 요청 URL 전체는 남기지 않는다.

### 5.5 코드 구조 (Claude 판단)

- `src/lib/calendar.ts` (순수, import 없음, `node:test`): 달 목록 만들기, 한 달의 날짜 칸(요일 맞춘 빈칸 포함), 고르기 규칙(`nextSelection`), 범위 요약 문구, 박·일 계산, 요일 이름. 날짜는 `YYYY-MM-DD` 문자열로 다룬다.
- `src/lib/holidays.ts` (순수, import 없음): API 응답 → 날짜 배열 파싱.
- `src/lib/holidays-api.ts` (`server-only`): fetch + 캐시 + 실패 처리.
- `src/app/trips/date-range-picker.tsx` (`"use client"`): 트리거 버튼, 숨은 입력, 달력 시트. 네이티브 `<dialog>`(`showModal`)로 포커스 가두기와 Esc 를 얻는다.
- `src/app/trips/trip-form.tsx`: 날짜 칸 두 개를 `DateRangePicker` 로 바꾼다. 나머지는 그대로다.
- 날짜 버튼마다 `aria-label` 을 단다(예: "2027년 1월 1일 금요일, 공휴일, 시작"). 고른 날은 `aria-pressed` 로 표시한다.

## 6. 구현자에게 맡기는 것

- 시트·창의 정확한 크기, 띠 모양, 색(다크 모드 포함). 참고 화면 느낌과 #11 의 zinc 계열 스타일을 따른다.
- 범위 밖 연도의 공휴일을 받는 방식(연도별 병렬 호출 등).
- 키보드로 날짜 사이를 옮기는 기능(방향키)은 넣으면 좋지만 필수는 아니다. Tab 으로 날짜 버튼에 닿고 Enter 로 고를 수 있으면 된다.

## 7. 공휴일 완료 기준

사용자 결정: 실제 응답 예시를 받아 시험 데이터로 쓴다.

- 사용자가 인증키를 받은 뒤 브라우저로 아래 주소를 열어 나온 응답을 채팅에 붙인다. 키는 주소에만 있고 응답에는 없다.
  `https://apis.data.go.kr/B090041/openapi/service/SpcdeInfoService/getRestDeInfo?serviceKey=<키>&solYear=2026&numOfRows=100&_type=json`
  - 오류가 나면 `&solMonth=05` 를 붙인 주소의 응답도 받는다(월 파라미터가 필수인지 판단).
- 구현은 응답을 기다리지 않고 진행한다. 응답이 오면 그대로 시험 데이터(`src/lib/holidays.test.mjs`)로 넣고, 파서와 호출 방식(연 1회 / 월 12회)을 맞춘다.
- PR 을 draft 에서 내리기 전 조건: 실제 응답으로 만든 시험이 통과한다. 응답이 아직 없으면 draft 로 두고 사용자에게 다시 요청한다.
- 머지 뒤: 사용자가 Vercel 에 키를 넣은 프로덕션에서 공휴일(예: 2027-01-01)이 빨갛게 보이는지 확인한다.
