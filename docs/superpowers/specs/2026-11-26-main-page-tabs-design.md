# 메인 페이지와 아래 탭: 홈 · 함께 · 내 여행 (#122)

2026-11-26. 빌더 확인(서브에이전트) 반영. 시안: https://claude.ai/artifact/V9RvYw8ovzFLfmDaJXF7rw (1~6번 화면). 시안의 홈(1번)은 목록 요약이 들어 있던 앞 판이고, 이 문서 §5.3 이 최종이다(홈은 다음 여행 카드만).

## 1. 왜

사용자가 그린 큰 그림(#122, 2026-11-25):

> 나는 결국엔 메인페이지를 만들고, 내 여행, 함께 가는 여행 이런식으로 분리해서 볼 수 있게 하고 싶은건데. 내 여행은 여행 기록을 담아놓는 추억인거지. 그게 혼자가 됐든, 여럿이 됐든

이 세션에서 사용자가 더한 것:

- 여행의 목적은 추억 쌓기만이 아니다. 자랑하려고일 수도 있고 다른 이유도 있다. 그래서 **메인(홈)에는 메인만의 기능**을 넣으려고 한다. 피드는 한 예시일 뿐이고, 이번에는 **후일을 도모하기 위한 기틀만** 마련한다.
- 보통 앱처럼 **메인과 메뉴가 따로** 있어야 한다. 메뉴는 **아래 탭**으로 한다.
- 홈 주소는 `/` 로 한다.

지금은 로그인하면 `/trips`("내 여행", 다가오는 여행 / 지난 여행 / 떼어 낸 기록) 한 화면뿐이고, 함께 가는 여행과 추억을 나눠 볼 곳도, 홈만의 기능을 얹을 자리도 없다.

## 2. 목표 · 비목표 · 반목표

- 목표
  - 로그인한 사람에게 아래 탭 세 칸(**홈 · 함께 · 내 여행**)이 보인다. 넓은 화면(`sm` 이상)에서는 같은 세 칸이 위쪽 머리에 들어간다.
  - **홈**(`/`)은 목록을 되풀이하지 않는 독립된 자리다. 지금은 "다음 여행" 카드 하나만 둔다. 나중 기능은 홈에 칸으로 더한다.
  - **함께**(`/together`)는 지금 다른 사람과 같이 쓰는, 아직 끝나지 않은 여행의 목록이다.
  - **내 여행**(`/mine`)은 혼자 가는 앞으로의 여행("앞으로")과 다녀온 모든 여행("추억")이다. 추억에는 올해·모두 여행 수, 함께 간 사람 수, 사람마다 "N번 함께", 연도별 목록이 있다.
  - 여행 하나를 열면(`/trips/<id>`) 탭이 없다. 위쪽 "← 내 여행"은 "← 뒤로"가 된다.
  - 옛 주소 `/trips` 는 `/` 로 보낸다(북마크가 깨지지 않게).
- 비목표 (다음 이슈로 남긴다, §7)
  - 홈만의 기능(피드, 자랑하기 등). 이번에는 자리만.
  - 추억의 다녀온 곳 지도, 내가 쓴 돈.
  - 친구 관계, 공개 링크, 사진 올리기.
  - 여행 화면 안의 모양 바꾸기("← 뒤로" 한 곳 말고).
- 반목표 (돌아가도 실패인 것)
  - 탭 막대가 여행 화면의 예산 줄·날짜 막대, 새 여행·고치기·초대 화면, 로그인 화면에 나타난다.
  - 접근할 수 없는 여행이나 남의 정보(이메일, 계정 번호)가 어떤 목록·숫자에든 섞인다. 함께 간 사람의 계정 번호가 브라우저로 나간다(#103 반목표와 같음).
  - 여행이 어느 탭에도 보이지 않는다(§5.2 의 나누기는 모든 여행을 빠짐없이 한 곳 이상에 둔다).
  - 비로그인 사용자가 `/together`·`/mine`·`/` 에서 남의 데이터를 보거나 오류 화면을 본다.
  - 옛 `/trips` 링크(북마크, 초대 화면의 버튼, 나가기 뒤 이동)가 404 가 된다.

## 3. 제약

- `CLAUDE.md` 규칙: Server Component 기본, `'use client'` 는 말단만(탭 막대의 현재 칸 표시, "← 뒤로"). DB 접근은 `src/db/` 로만, 사용자 데이터 쿼리는 `src/db/queries/<테이블>.ts` 에 `import "server-only"`, 첫 인자 `userId`. 현재 사용자는 `getCurrentUser()`. 비로그인은 `redirect("/")`. 사용자에게 보이는 문구는 한국어.
- 여행 접근은 `accessibleTrips(userId)`(`trips` 를 별칭 없이 FROM 에 둔 쿼리 안에서만). 하위 데이터는 같은 SQL 문에 접근 조건을 넣는다(`docs/status.md` '쿼리 구조').
- 스키마는 바꾸지 않는다(마이그레이션 없음). 위험 경로(`next.config.ts`, `src/lib/session.ts` 등)도 건드리지 않는다. `/trips` → `/` 이동은 `next.config.ts` redirects 가 아니라 `src/app/trips/page.tsx` 의 `redirect("/")` 로 한다.
- Next 16 의 route group(`(folder)`)은 URL 에 들어가지 않고 일부 경로만 레이아웃을 함께 쓰게 한다(`node_modules/next/dist/docs/01-app/03-api-reference/03-file-conventions/route-groups.md`). 다른 group 끼리 같은 URL 이 되면 오류다.
- 단위 시험 대상 순수 모듈(`src/lib/*.ts`)은 다른 모듈을 import 하지 않는다(`node --test`). DB 시험은 없다.
- 디자인 토큰만 쓴다(`globals.css`, `src/app/ui/styles.ts`). `dark:`·`zinc-*` 를 쓰지 않는다.
- `next.config.ts` 에 `cacheComponents: true` 가 켜져 있다. 요청마다 다른 데이터(`getCurrentUser()` 등)를 읽는 부분은 `Suspense` 안에 둔다(지금 페이지들처럼). `(tabs)/layout.tsx` 의 로그인 확인도 같다.
- 이름 뒤 조사: 지금 `companionsLine`(`src/lib/trip-records.ts`)처럼 이름마다 "님"을 붙여 "과"로 잇는다(받침 문제를 피함). 시안의 "민수·지영과 함께"는 실제로 "민수님, 지영님과 함께"가 된다.

## 4. 방법

### 4.1 사용자가 이 세션에서 고른 것 (순서대로)

1. **추억을 어디에**: 메인에 다 펼치기 / **메인에는 요약, 자세한 것은 따로** → 따로.
2. **표에 안 맞는 여행**: A 표 그대로(함께 = 사람 있는 모든 여행, 끝난 것 포함) / **B 시간도 보기**(함께 = 아직 끝나지 않은 함께 여행, 끝나면 추억으로) → B.
3. **메뉴**: **아래 탭** / 메뉴 없이 메인에서 들어가기 → 아래 탭.
4. **홈의 역할**: 홈은 두 탭의 요약이 아니라 **홈만의 기능을 얹을 기틀**. 지금은 다음 여행 카드만.
5. **주소**: `/main` / **`/`** → `/`.

### 4.2 탭 막대를 붙이는 방법 (사용자가 A 를 고름)

| | 방법 | 장점 | 단점 |
|---|---|---|---|
| **A** | 세 탭 화면만 route group `src/app/(tabs)/` 로 묶고 그 `layout.tsx` 에 탭 막대를 둔다. 여행 화면·새 여행·초대는 group 밖 | 탭이 보이는 곳이 폴더로 정해져 실수할 여지가 없다. 탭을 더하기 쉽다 | `/` 가 로그인 화면이기도 해서 비로그인이면 레이아웃이 탭을 그리지 않아야 한다 |
| B | 앱 전체 레이아웃에 두고 현재 주소로 감출 화면을 고른다 | 처음이 가장 빠르다 | 화면이 늘 때마다 감출 목록을 고쳐야 하고, 빠뜨리면 예산 줄 위에 겹친다 |
| C | 세 화면이 각자 탭 막대를 넣는다 | 단순하다 | 세 번 되풀이, 고칠 때 세 곳 |

## 5. 설계

### 5.1 주소와 파일

| 화면 | 주소 | 파일 |
|---|---|---|
| 로그인(비로그인) · 홈(로그인) | `/` | `src/app/(tabs)/page.tsx` (지금 `src/app/page.tsx` 를 옮김) |
| 함께 | `/together` | `src/app/(tabs)/together/page.tsx` |
| 내 여행 | `/mine` | `src/app/(tabs)/mine/page.tsx` |
| 탭 틀 | — | `src/app/(tabs)/layout.tsx` + 말단 클라이언트 `tab-bar.tsx` |
| 옛 목록 | `/trips` | `src/app/trips/page.tsx` → `redirect("/")` 만 |
| 여행·새 여행·고치기·초대 | 그대로 | group 밖(탭 없음) |

- `src/app/page.tsx` 는 없앤다(`(tabs)/page.tsx` 와 같은 `/` 라 함께 두면 오류).
- `(tabs)/layout.tsx`: `getCurrentUser()` 로 로그인 여부를 보고, 로그인했을 때만 탭 막대를 그린다. 비로그인 `/` 는 지금 로그인 화면 그대로(가운데 정렬, 탭 없음).
- `/` 페이지: 비로그인이면 지금 로그인 화면, 로그인이면 홈(§5.3). 지금의 `redirect("/trips")` 는 없앤다.
- `/together`·`/mine`: 비로그인이면 `redirect("/")`.
- 탭 막대
  - 휴대폰(`sm` 미만): 화면 아래 고정, 세 칸 같은 폭, 칸마다 선 아이콘 + 글(홈 · 함께 · 내 여행), 누를 곳 높이 56px 이상, 아래 safe-area 여백. 본문은 막대에 가리지 않게 아래 여백을 둔다.
  - 넓은 화면(`sm` 이상): 아래 막대 대신 위쪽 머리 안에 같은 세 칸(시안 5번).
  - 현재 칸은 `aria-current="page"` 와 굵은 글·진한 색. 현재 칸은 `usePathname()` 으로 고른다(이것만 클라이언트).
  - 아이콘은 시안의 인라인 선 SVG(새 의존성 없음), `aria-hidden`.
- 탭 화면 머리
  - 홈: 앱 이름(작은 노선 + "Trip Planner"), "+ 새 여행", 로그아웃.
  - 함께·내 여행: 제목(h1)과 한 줄 설명, "+ 새 여행". 로그아웃은 홈 머리에만 둔다(내 판단: 자주 쓰지 않음).
  - 넓은 화면에서는 위쪽 머리 한 줄(앱 이름 · 세 칸 · "+ 새 여행" · 로그아웃)이 모든 탭에 같고, 각 화면의 제목은 그 아래에 둔다.

### 5.2 여행 나누기 규칙

`listTrips(userId)` 가 주는 모든 여행(접근 가능 = 주인이거나 함께하는 사람, 기록 포함)을 오늘(`todayInSeoul()`) 기준으로 나눈다. 순수 함수로 `src/lib/trip-groups.ts`(새 파일, import 없음)에 두고 시험한다.

- **함께하는 여행**: `trip_members` 행이 한 개 이상인 여행(내가 주인이든 함께하는 사람이든). 떼어 낸 기록은 멤버가 없어 언제나 아니다. 초대 링크만 있고 아무도 들어오지 않은 여행은 아니다.
- **끝남**: `endDate < today`. 여행 중(`startDate <= today <= endDate`)은 끝나지 않음.

| 여행 | 홈 "다음 여행" 후보 | 함께 탭 | 내 여행 "앞으로" | 내 여행 "추억" |
|---|---|---|---|---|
| 함께하는, 끝나지 않음 | O | O | | |
| 혼자, 끝나지 않음, 기록 아님 | O | | O | |
| 기록, 끝나지 않음 | | | O | |
| 끝남 (혼자·함께·기록 모두) | | | | O |

- 모든 여행은 함께 탭, 앞으로, 추억 중 정확히 한 곳에 있다(시험으로 확인).
- **다음 여행**: 후보 중 시작 날짜가 가장 이른 것 하나(여행 중이면 그 여행). 같은 시작이면 지금 `splitTrips` 의 순서(끝 날짜, 만든 시각). 기록은 후보가 아니다(내가 나온 여행이라 "갈 여행"이 아님, 내 판단).
- 함께 탭·앞으로의 순서: 지금 `splitTrips` 의 upcoming 순서(시작 날짜 가까운 순).
- 추억의 순서: 시작 날짜의 연도(서울 날짜 문자열 그대로)로 묶고, 연도는 최근 먼저, 연도 안에서는 지금 `splitTrips` 의 past 순서(최근에 끝난 순).
- 지금의 "떼어 낸 기록" 칸(날짜와 관계없이 맨 아래)은 없어지고, 기록도 위 표처럼 날짜로 나뉜다. 기록 이름표("OO님 여행에서 · M/D 떼어 냄", `recordBadge`)는 그대로 붙는다. `splitRecords` 는 쓰지 않게 되면 지운다.

### 5.3 홈 (`/`, 로그인)

```
 [노선] Trip Planner        [+ 새 여행] 로그아웃
 다음 여행
 ┌───────────────────────────────┐
 │ 부산 먹방 여행            D-3  │
 │ 부산, 12/1–12/3 · 민수·지영과 함께 │
 │ ●━●━●  (노선, lg)              │
 └───────────────────────────────┘
 (나중 기능은 이 아래에 칸으로)
```

- 카드 한 장 전체가 여행 화면으로 가는 링크. 내용: 제목, 남은 날, "목적지, 기간", 함께하는 사람이 있으면 "OO님, OO님과 함께"(3명까지, 넘으면 "OO님, OO님 외 N명과 함께"), 노선(`MiniLine` lg).
- 남은 날 표시: 시작 전이면 "D-N"(내일이면 "D-1"), 여행 중이면 "여행 중 · N일째"(첫날 1일째). 순수 함수로 `trip-groups.ts` 또는 `trip-dates.ts` 에 둔다. 지금 목록의 `tripCountdown`("N일 남음")은 함께 탭·앞으로 줄에서 계속 쓴다.
- 남이 만든 여행이면 지금처럼 "OO님의 여행" 이름표.
- 다음 여행이 없을 때
  - 여행이 하나도 없으면: "아직 여행이 없어요" + "첫 여행을 만들거나, 친구에게 받은 초대 링크를 열어 함께 가는 여행에 들어가 보세요." + "새 여행 만들기" 버튼(시안 4번).
  - 여행은 있는데 다음 여행 후보가 없으면(지난 여행만, 또는 끝나지 않은 것이 떼어 낸 기록뿐): "다가오는 여행이 없어요" + "새 여행 만들기" 버튼 + "내 여행에서 추억 보기" 링크(`/mine`).
- 홈은 "칸"을 쌓는 구조로 만든다: `(tabs)/page.tsx` 는 칸 컴포넌트(지금은 `NextTripSection` 하나)를 차례로 놓고, 칸마다 자기 데이터를 읽고 `Suspense` 로 감싼다. 나중 기능은 칸 하나를 더하는 것으로 끝나게 한다.

### 5.4 함께 탭 (`/together`)

- 제목 "함께 가는 여행", 설명 "다른 사람과 같이 계획하는 여행이에요. 여행이 끝나면 내 여행의 추억으로 옮겨 가요."
- 줄 하나(지금 `TripRow` 모양): 제목(+ 남이 만든 여행이면 "OO님의 여행" 이름표), "목적지, 기간 · 남은 날(tripCountdown)", 함께하는 사람 이름 줄, 노선.
- 함께하는 사람 이름 줄: 나를 뺀 사람(주인 + 멤버) 이름을 " · " 로, 3명까지, 넘으면 "외 N명". 순서는 주인 먼저, 그다음 참여한 순서(`listTripPeople` 과 같은 순서).
- 홈의 다음 여행도 여기에 그대로 있다.
- 비었을 때: "함께 가는 여행이 없어요" + "여행을 열고 초대 링크로 함께 갈 사람을 불러 보세요."

### 5.5 내 여행 탭 (`/mine`)

- 제목 "내 여행", 설명 "혼자 간 여행, 함께 간 여행, 떼어 낸 기록까지 내 여행을 모두 모았어요."
- **앞으로** 묶음(비면 감춤): §5.2 의 앞으로 여행, 지금 `TripRow` 모양(남은 날 포함). 아래 작은 글 "함께 가는 여행은 함께 탭에 있어요."는 함께 탭에 여행이 있을 때만(내 판단).
- **추억** 묶음
  - 숫자 세 칸: 올해(추억 중 시작 연도 = 오늘의 연도인 수), 모두(추억 수), 함께 간 사람(§5.6 의 서로 다른 사람 수).
  - 함께 간 사람 칩: "이름 N번 함께", 횟수 많은 순, 같으면 이름 순(`localeCompare("ko")`). 12명까지, 넘으면 "외 N명" 한 칩. 한 명도 없으면 칩 줄을 감춘다(숫자 칸은 "0명", 내 판단: 혼자 여행만 한 사람에게 빈 안내는 불필요).
  - 아래 작은 글 "같은 사람과 여러 번 가도 한 명으로 세요."
  - 지도·쓴 돈 자리: 점선 칸 두 개 "다녀온 곳 지도 / 내가 쓴 돈 · 다음에 더해요". 시안 3번에서 사용자가 본 모양이다. 지도·쓴 돈 이슈가 들어가면 그 칸으로 바뀐다.
  - 연도별 목록: "2026년 · 3번" 머리 아래 지금 `TripRow` 모양(흐린 노선). 함께 간 여행이면 "목적지, 기간 · OO님, OO님과" 처럼 이름을 붙인다(3명까지, 넘으면 "OO님, OO님 외 N명과"). 기록은 이름표.
- 추억이 비면 숫자·칩·자리 표시·목록 없이 "다녀온 여행이 아직 없어요. 여행이 끝나면 여기에 모여요." 앞으로도 추억도 없으면 홈과 같은 "아직 여행이 없어요" 안내.

### 5.6 함께 간 사람 세기

- 여행마다 "함께한 사람"
  - 기록 아닌 여행: 그 여행의 주인 + `trip_members` 의 사람, 나 제외.
  - 기록 여행: `trip_record_companions` 의 사람(이미 나 제외, 주인이었던 사람 포함).
- 추억(끝난 여행)에 대해서만 센다. 서로 다른 사람 = 계정 번호(`user.id`)로 가른다. 사람마다 횟수 = 그 사람이 함께한 추억 여행의 수.
- 계정 번호는 서버 안에서만 쓴다. 쿼리 결과의 `userId` 는 집계 순수 함수(`countCompanions`, `trip-groups.ts`)로만 넘어가고, 화면 컴포넌트에는 `{ name, count }` 와 여행별 이름 목록만 간다. 모든 화면이 Server Component 이고 클라이언트 컴포넌트(탭 막대, "← 뒤로")에는 사람 데이터를 넘기지 않는다.
- 알려진 한계(받아들임): 떼어 낸 기록이 없던 옛 이탈(#103 전)이나, 나는 남고 다른 사람이 나간 함께 여행에서는 그 사람이 더는 멤버가 아니라 세지 않는다. 같은 이름의 다른 사람은 칩이 둘이 된다.

### 5.7 데이터

- `listTrips(userId)` 를 넓히거나 새 쿼리를 더해, 여행마다 "나를 뺀 함께한 사람" `{ userId, name }[]` 과 멤버 여부(함께하는 여행인지)를 얻는다. 한 화면 요청에 쿼리 두세 번 이내로 한다(여행마다 쿼리하지 않는다).
  - 제안: (1) 지금 `listTrips` + `hasMembers`(EXISTS) 칸, (2) 새 `listTripCompanions(userId)` — 접근 가능한 여행들에 대해 주인·멤버·기록 동행을 UNION 한 `{ tripId, userId, name }` 행(나 제외). 둘 다 `accessibleTrips(userId)` 를 같은 문에 둔다. 세부 SQL 은 빌더 판단.
  - 이메일은 고르지 않는다(지금 규칙).
- 같은 요청 안에서 홈·탭이 같은 결과를 나눠 쓸 일은 없다(탭마다 따로 요청). 레이아웃은 사용자 확인만 한다.
- 무효화: 여행·멤버를 바꾸는 Server Action 의 `revalidatePath("/trips")` 를 `revalidatePath("/")`·`"/together"`·`"/mine"` 으로 바꾼다(또는 `revalidatePath("/", "layout")` 한 번 — 빌더 판단. 앱 전체를 무효화하는 비용이 작으면 후자가 빠뜨림이 없다).

### 5.8 "/trips" 를 가리키던 곳

- `src/app/trips/page.tsx`: 목록을 지우고 `redirect("/")` 만.
- `src/app/trips/[id]/page.tsx` 의 "← 내 여행" → "← 뒤로"(§5.9).
- `src/app/trips/actions.ts`(여행 지우기 뒤 `redirect("/trips")`), `member-actions.ts`(나가기 뒤), `new/page.tsx`(`cancelHref`), `not-found.tsx`, `invite/[token]/page.tsx`(로그인했을 때 버튼), `src/app/invite/actions.ts`: `/trips` → `/`. 그 밖에 `"/trips"` 문자열을 grep 으로 모두 찾아 같은 판단을 한다(`/trips/` 로 시작하는 여행 주소는 그대로).
- `src/app/page.tsx` 의 주석("로그인 뒤에는 여기서 목록으로 보낸다")은 파일과 함께 없어진다.

### 5.9 여행 화면의 "← 뒤로"

- 말단 클라이언트 컴포넌트. 앱 안에서 이동해 왔으면 브라우저 뒤로(`router.back()`), 링크를 바로 열었거나 앞 기록이 이 앱이 아니면 `/` 로 간다.
- 판별 방법은 빌더 판단(예: 탭·목록 링크에서 들어올 때 표시를 남기거나, `document.referrer` 가 같은 출처인지). JS 가 없을 때도 `<a href="/">` 로 동작해야 한다.
- 새 여행 만들기(`/trips/new` → 만든 여행)와 고치기(`/trips/<id>/edit` → 여행)를 거친 뒤 "← 뒤로"가 다시 양식으로 가지 않게 한다(양식 제출 뒤 이동이 `redirect` 라 기록이 쌓이는지 빌더가 확인. 쌓이면 "← 뒤로"는 그때 `/` 로).

### 5.10 시험과 확인

- 단위 시험(`src/lib/trip-groups.test.mjs`): 나누기 표의 모든 칸, 여행 중·오늘 끝나는 여행·오늘 시작하는 여행, 기록의 앞으로/추억, 모든 여행이 정확히 한 곳, 다음 여행 고르기(기록 제외, 같은 시작일), 연도 묶기·순서, "올해" 세기, `countCompanions`(같은 사람 여러 여행, 기록 동행 + 멤버 합치기, 출력에 userId 없음), "D-N"/"여행 중 · N일째".
- 브라우저 확인(`run` 스킬, Playwright): 휴대폰 폭에서 세 탭 이동·현재 칸 표시·막대가 본문을 가리지 않음, 넓은 화면의 위쪽 메뉴, 여행 화면에 탭이 없음·예산 줄 그대로, 비로그인 `/` 는 로그인 화면(탭 없음), 비로그인 `/together`·`/mine` → `/`, `/trips` → `/`, 빈 상태 세 가지, 다크 모드. 임시 테스트 계정으로 한다(#103 과 같은 방법).
