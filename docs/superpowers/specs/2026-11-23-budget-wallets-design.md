# 모임 통장·개인 통장 지출 (#89)

2026-11-23. 사용자 승인(2026-11-24).

## 1. 왜

지금 예산(#14)은 여행 하나에 하나이고, 함께하는 사람(#15) 모두가 같은 예산과 지출을 보고 고친다. 실제 여행은 돈 쓰는 방식이 여럿이다(사용자).

- **모임 통장으로 가는 여행**(사용자의 경우): 지인과 모임 통장을 쓴다. 출발지가 달라 각자의 표 값이 다르지만 모두 모임 통장에서 나가고, 총 예산에서 빠지며, 누구 표가 얼마였는지 함께 본다. 차이를 정산하지는 않는다.
- **같이 가되 비용은 각자 내는 여행**: 내 지출을 남에게 보일 이유가 없다. 로그인한 본인만 본다.
- **둘 다**: 모임 통장 여행에서도 기념품처럼 내 돈으로 사는 게 있다.

또 표처럼 **미리 결제한 지출**은 일정을 완료하기 전에도 실제 금액이 정해져 있는데, 지금은 완료해야 실제 지출 칸이 열린다.

사람마다 다른 표 값과 동선은 #90(사람별 일정·동선)이 다룬다. #90 에서 "내 KTX", "지인 KTX"가 대상이 다른 별개 일정이 되면, 각 일정의 금액이 이 문서의 규칙을 그대로 따른다(#90 댓글에 메모함). 그래서 이 이슈에서는 "일정 하나에 사람별 금액 나눠 적기"를 만들지 않는다.

## 2. 목표 · 비목표 · 반목표

- 목표
  - 여행마다 지출 방식을 고른다: **모임 통장 / 각자 / 둘 다**.
  - 지출 행마다 "누구 돈"이 있다: **모임** 또는 **내 돈**. 내 돈 지출은 적은 사람만 본다.
  - 예산도 사람마다: 각자·둘 다 여행에서 사람마다 **내 예산**(총액)을 따로 정하고, 본인만 본다.
  - 미리 결제한 지출: 완료하지 않아도 실제 지출을 적을 수 있다.
- 비목표
  - 일정 하나에 사람별 금액 나눠 적기(→ #90 사람별 일정).
  - 정산(누가 누구에게 얼마). 사용자: "차이는 안 맞춰. 기록만 남으면 돼."
  - 내 돈 지출을 골라서 남에게 공개하기.
  - 사람마다 다른 통화 설정.
  - 여행지로 통화 미리 채우기(→ #100).
- 반목표 (돌아가도 실패인 것)
  - 남의 내 돈 지출이나 내 예산이 어떤 경로로든(목록, 합계, 날짜별 합계, 양식 처음 값, 오류 문구의 금액·건수, 응답 크기 차이가 아닌 명시적 값) 다른 사람에게 보인다. **여행 주인에게도.**
  - 남의 내 돈 행을 고치거나 지울 수 있다(id 를 섞어 보내도).
  - 방식을 바꾸면 이미 적은 기록이 사라지거나, 숨었던 내 돈 지출이 드러난다.
  - 다른 사람이 일정을 지워서 내 내 돈 기록이 경고 없이 사라진다.
  - 지금 쓰는 모임 통장 여행(기존 모든 여행)의 화면·숫자가 바뀐다.
  - 마이그레이션이 기존 데이터를 지우거나 바꾼다.

## 3. 제약

- 마이그레이션 PR(`CLAUDE.md` '마이그레이션 PR'): 자동 머지 없음, 사람이 SQL 을 보고 `human-approved` → `npm run db:migrate`(실행 직전 사람 확인) → 자동 머지. 위험 경로는 `src/db/schema.ts`, `drizzle/**`. 새 의존성 없음.
- 인증·소유권 코드 → `/security-review` 대상.
- 여행 접근은 `accessibleTrips(userId)` 하나. 하위 쿼리는 하위 id·여행 id·접근 조건을 한 SQL 문에 함께 묶는다(#14 §3).
- neon-http 는 대화형 트랜잭션이 없다. 여러 행·조건부 쓰기는 한 문(조건부 insert/update, 데이터를 바꾸는 CTE).
- 단위 시험 대상 순수 모듈(`src/lib/*.ts`)은 다른 모듈을 import 하지 않는다. 시험은 `src/**/*.test.mjs` 이고 DB 시험은 없다.
- 사용자에게 보이는 문구는 한국어.

## 5. 설계

### 5.1 개념

| 방식 | 모임 예산 | 내 예산 | 새 지출의 "누구 돈" |
|---|---|---|---|
| 모임 통장 (`shared`) | 있음, 모두가 봄 | 없음 | 늘 모임 |
| 각자 (`personal`) | 없음 | 사람마다, 본인만 | 늘 내 돈 |
| 둘 다 (`both`) | 있음, 모두가 봄 | 사람마다, 본인만 | 지출마다 고름(기본 모임) |

- **함께 쓰는 것:** 통화 설정(예산 통화·현지 통화·예정 환율)은 여행에 하나. 일정·메모·완료·가 볼 곳·지도·동선은 지금처럼 모두가 함께 쓴다. 메모에 적은 금액은 보인다(숨기려면 금액 칸).
- **나만 보는 것:** 내 예산, 내 돈 금액(일정에 붙은 것과 일정 밖 항목).
- **방식은 여행 주인만** 고른다(초대 링크처럼 여행 전체 규칙). 새 여행·기존 여행의 기본은 모임 통장. 모임 예산 총액은 지금처럼 함께하는 사람 누구나 고친다. 내 예산은 본인만.
- **방식을 바꾸면(사용자 ①):** 이미 적은 행은 그대로 둔다. 모임 행은 계속 모두가, 내 돈 행은 계속 본인만 본다. 방식은 새로 적을 때의 "누구 돈"과 보이는 카드를 정한다. 바꾸기를 막는 경우는 없다.

### 5.2 DB (마이그레이션 0008, 파괴적 아님)

```
trip_budgets
  + mode text not null default 'shared'  check (mode in ('shared','personal','both'))
  ~ total_amount  NOT NULL 풀기 (모임 예산 총액. 각자 여행은 비어 있을 수 있음)
    check 그대로(값이 있으면 0 이상 10^12 미만)

budget_items
  + owner_user_id text null references "user"(id) on delete cascade   -- null = 모임
  ~ unique(schedule_item_id) → 아래 둘로 바꿈
      unique(schedule_item_id) where owner_user_id is null              -- 일정마다 모임 행 하나
      unique(schedule_item_id, owner_user_id) where owner_user_id is not null  -- 사람마다 하나
  + index(trip_id, owner_user_id)  (필요하면, 빌더 판단)

trip_personal_budgets   (새 테이블)
  trip_id uuid references trips(id) on delete cascade
  user_id text references "user"(id) on delete cascade
  total_amount bigint not null  check (0 이상 10^12 미만)
  currency text not null  check (~ '^[A-Z]{3}$')   -- 정할 때의 예산 통화(§5.5 통화가 바뀐 내 예산)
  created_at, updated_at
  primary key (trip_id, user_id)
```

- 기존 행: `mode = 'shared'`, `owner_user_id = null` → 지금과 똑같이 보인다.
- 고유 색인을 지우고 다시 만드는 것, NOT NULL 풀기, 칸·테이블 추가는 데이터를 지우거나 바꾸지 않는다. PR 본문에 SQL 전문과 "파괴적 아님" 판정. (drizzle 이 부분 고유 색인을 `ON CONFLICT` 대상으로 쓰려면 `ON CONFLICT (schedule_item_id) WHERE owner_user_id IS NULL` 처럼 조건을 함께 적어야 한다 — §5.4.)
- 금액의 통화는 지금처럼 그 여행 `trip_budgets` 의 예산·현지 통화여야 한다(쓰기 문이 확인).

### 5.3 누가 무엇을 보나 (보안의 중심)

- **조건 함수 하나:** `src/db/queries/budget.ts` 에 `visibleToUser(userId)` = `owner_user_id IS NULL OR owner_user_id = userId`. 지출 행을 읽거나 쓰는 **모든** 쿼리가 `itemInAccessibleTrip` 과 함께 이것을 건다. 원시 SQL 문에는 같은 조건의 `sql` 조각 버전을 쓴다.
- 쓰기는 더 좁다: 모임 행은 접근 가능한 사람 누구나, **내 돈 행은 `owner_user_id = userId` 인 본인만**. `owner_user_id` 는 폼 입력으로 받지 않는다. 서버가 "모임 / 내 돈" 선택(불리언)을 받아 `null` 또는 `user.id` 로 정한다.
- 사람별 예산(`trip_personal_budgets`)은 `user_id = userId` 행만 읽고 쓴다.
- **서버 쪽 이중 확인:** `loadBudget` 은 쿼리가 돌려준 행 중 `owner_user_id` 가 `null` 도 `userId` 도 아닌 행을 버리고 `console.error("[budget-visibility]")` 를 남긴다. 이 갈래 나누기는 순수 함수로 `src/lib` 에 두고 단위 시험을 붙인다(남의 행이 섞여 들어와도 화면 데이터에 안 나가는지).
- **오류 문구:** 통화 바꾸기가 남의 숨은 금액 때문에 막혀도 지금 문구 "이미 적은 금액이 있어 통화를 바꿀 수 없어요." 그대로. 누가·얼마·몇 건인지 말하지 않는다(사용자 2-(가)). "누군가 그 통화로 적었다"는 사실만은 짐작할 수 있음을 받아들인다.
- **일정 밖 항목 상한(300, #14)** 은 "모임 행 + 내 내 돈 행"으로 센다(`countBudgetItems` 에 `visibleToUser`). 남의 숨은 행 때문에 막히거나 그 수를 짐작하지 않게.
- 여행 주인도 남의 내 돈 행·내 예산을 못 본다. 여행 삭제는 지금처럼 모두 cascade.

### 5.5 계산 (`src/lib/budget.ts`)

- `BudgetLine` 에 `mine: boolean`(내 돈 행인가)을 더한다. 화면에 오는 행은 모임 행이거나 내 행뿐이다(§5.3).
- `summarizeBudget` 은 그대로 두고 두 번 부른다: 모임 행 + 모임 총액, 내 행 + 내 예산 총액. `BudgetSettings.totalAmount` 가 nullable 이 되므로 요약에 넘길 총액은 따로 받게 바꾼다(빌더 판단).
- `totalsByPeriod` 도 갈래마다. [N일차] 카드도 모임·내 것을 따로 보인다.
- 내 예산을 아직 안 정했으면 내 카드는 합계만 보이고 막대 대신 "내 예산 정하기"(§5.7). 모임 총액이 비었는데 모임 카드를 보여야 하면(각자 → 둘 다 등) 같은 방식으로 "모임 예산 정하기".
- **통화가 바뀐 내 예산** *(Claude 의 판단, 빌더 검토에서 나옴)*: 예산 통화는 지출 행이 하나도 없을 때만 바뀐다(#14 §5.2). 그런데 B 가 내 예산만 정하고 지출은 안 적었으면, A 가 예산 통화를 ₩ → $ 로 바꿀 수 있고 B 의 저장된 최소 단위 정수가 다른 통화로 읽힌다(₩1,000,000 → $10,000.00). B 의 예산은 A 에게 안 보이므로 아무도 모른다. 그래서 내 예산 행에 정할 때의 통화를 함께 저장하고, 여행 예산 통화와 다르면 내 카드는 막대 대신 "예산 통화가 바뀌었어요. 내 예산을 다시 정해 주세요 (전에 정한 값: ₩1,000,000)" 를 보인다. 통화 바꾸기를 막지 않으니 남의 내 예산이 있다는 사실도 드러나지 않고, 값이 조용히 다른 통화로 읽히지도 않는다. 모임 총액의 같은 문제는 바꾸는 사람이 같은 양식에서 보므로 지금 그대로 둔다.

### 5.6 미리 결제한 지출

- **일정 고치기 양식**에서 완료하지 않아도 실제 지출 칸을 보인다(지금은 `item.done || item.actual !== null` 일 때만). 처음엔 접힌 "실제 지출 적기"로 둬 휴대폰 양식이 길어지지 않게 한다(빌더 판단: 접힘/펼침 표현).
- **완료를 풀어도 실제를 지우지 않는다.** 지금의 확인 창("완료를 풀면 적어 둔 실제 지출 …도 지워져요")과 `undoScheduleItemAndClearActual` 의 실제 지우기를 없앤다. 실제를 지우려면 칸을 비우고 저장한다.
  - 이유: 미리 결제한 일정은 완료 전에도 실제가 있다. 또 완료는 함께 쓰는 값인데 실제는 사람마다라, 한 사람이 완료를 풀어 남의 실제를 지우면 안 된다.
- 완료 체크칸을 켜면 그 줄 아래에 실제 지출 칸이 열리는 지금 흐름(#14 §5.7.3)은 그대로. 켠 사람의 칸만 열린다. 둘 다 여행이면 이 칸에도 `[모임] [내 돈]` 전환.

### 5.7 화면

예산 시트(#97 바텀 시트)와 아래 예산 줄, 일정 양식만 바뀐다. 모임 통장 여행은 지금과 똑같다.

**예산 시트 카드**

```
모임 통장            각자                 둘 다
┌ 모임 예산 ┐        ┌ 내 예산 🔒 ┐       ┌ 모임 예산 ┐
│ (지금 카드)│        │ (같은 모양) │       │ (지금 카드)│
└──────────┘        └───────────┘       ├ 내 예산 🔒 ┤
                                         │ (같은 모양) │
                                         └───────────┘
```

- 내 카드에는 "나만 보여요" 표시(자물쇠 아이콘 + 글자, 빌더 판단).
- 방식을 바꾼 뒤 모임 행이 남은 각자 여행은 모임 카드도 보인다(§5.1 ①). 남은 게 없으면 숨긴다. 내 돈 행이 남은 모임 통장 여행도 같은 규칙으로 내 카드를 보인다.
- 일정 밖 항목 목록과 [+ 지출]은 카드마다(모임 카드의 [+ 지출]은 모임 행, 내 카드는 내 돈 행). 

**아래 예산 줄(#97)**: 모임 통장 → 모임 막대(지금), 각자 → 내 막대, 둘 다 → 막대 둘을 작게(모임 위, 내 것 아래). 휴대폰 너비에서 한 줄에 넣을지 두 줄로 할지는 빌더 판단(브라우저로 확인).

**예산 정하기 양식**: 통화 설정(함께) + 방식(주인에게만 고르기, 다른 사람에게는 "방식: 모임 통장 · 여행 주인이 정해요" 글자) + 모임 총 예산(모임·둘 다) + 내 예산(각자·둘 다). 내 예산 칸 옆에 "나만 보여요".

**일정 양식(둘 다 여행)**: 예상 비용 칸에 `[모임] [내 돈]` 전환. 같은 일정에 모임 금액과 내 돈 금액이 둘 다 있을 수 있으므로, 전환은 "어느 쪽 금액을 고치나"이고 각 쪽에 적어 둔 값이 따로 보인다. 각자 여행은 전환 없이 내 돈만, 모임 통장 여행은 지금 그대로.

```
  예상 비용   [모임] [내 돈]
              ₩ 60,000          ← [내 돈]을 누르면 내 값(₩8,000)으로 바뀜
```

- **한 번 저장에 무엇을 쓰나** *(Claude 의 판단)*: 둘 다 여행의 일정 양식은 모임 쪽과 내 돈 쪽 값을 **둘 다** 보내고, 서버는 처음 값과 달라진 쪽만 쓴다. 전환은 화면에서 어느 쪽을 보이느냐일 뿐, 전환 전에 고친 값이 사라지지 않는다. 고치기 양식의 "실제 지출 적기"와 완료 체크칸의 실제 지출 칸도 같은 전환을 따른다. 낡은 양식 막기(`actualShown`·`actualAllowedNow`)는 쪽마다 따로 한다.
- **방식을 바꾼 뒤 남은 반대쪽 금액** *(Claude 의 판단)*: 일정에 지금 방식이 쓰지 않는 쪽 행이 남아 있으면(예: 모임 → 각자 뒤 KTX 일정의 모임 예상 ₩60,000), 그 일정의 양식에는 방식과 상관없이 `[모임] [내 돈]` 전환을 보여 고치거나 비울 수 있게 한다. 남은 행이 없으면 방식대로(모임 통장은 전환 없이 모임, 각자는 전환 없이 내 돈). 완료 체크칸의 실제 지출 칸은 기본으로 방식의 쪽에 쓰고, 남은 반대쪽 행이 있으면 같은 전환을 보인다. 기존 여행에는 내 돈 행이 없으므로 화면이 바뀌지 않는다.

일정 줄 자체에는 지금처럼 금액을 보이지 않는다(#14·#53).

### 5.8 시험·확인

- 단위 시험: 행 갈래 나누기(남의 행 버리기 포함), 모임/내 요약 두 벌, "누구 돈" 입력 검증.
- 브라우저 확인(로컬 dev, 테스트 계정 둘, 같은 여행에 주인·함께하는 사람): 세 방식 각각에서 A 가 적은 내 돈이 B 화면·합계·[N일차]에 안 나오는지, B 가 A 의 내 돈 행 id 로 고치기·지우기를 보내면 "찾을 수 없음", 방식 바꾸기 뒤 보이는 카드, 일정 지우기 뒤 남의 내 돈이 일정 밖 항목으로 남는지, 나가기 뒤 내 돈·내 예산이 지워지는지, 미리 결제한 실제 지출과 완료 풀기.
