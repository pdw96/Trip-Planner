# Vercel 배포 한도 아끼기 설계 (작은 변경)

- 날짜: 2026-11-18
- 이슈: pdw96/Trip-Planner#29
- 상태: 승인됨 (2026-11-18)

## 의도
작업 브랜치에 push 할 때마다 Vercel 미리보기 배포가 생겨, 계정 전체에 걸리는 하루 배포 한도(무료 100회)가 금방 찹니다. 2026-11-18 에는 PR #27 의 미리보기가 한도에 걸렸습니다. 그날 계정 전체 배포 56회 가운데 42회가 미리보기였습니다.

이 앱의 미리보기로는 화면을 확인할 수 없습니다. Google 로그인 키가 없고, 미리보기 DB 에 마이그레이션도 적용하지 않습니다. 화면 확인은 로컬 dev 와 임시 테스트 계정으로 합니다(`docs/status.md`). 그래서 미리보기를 꺼도 잃는 것이 거의 없습니다.

## 목표 / 비목표
- **목표:** 작업 브랜치(`claude/*`, `ccr-*`)에서는 배포하지 않습니다. 앱과 상관없는 변경만 있으면 빌드를 건너뜁니다. `main` 의 프로덕션 배포는 그대로 둡니다.
- **비목표:**
  - job-hunter·erp 저장소 설정(다른 저장소)
  - Pro 플랜
  - CI(`check`, `human-gate`) 변경
- **반목표:** 앱 코드나 설정이 바뀌었는데 프로덕션 배포가 건너뛰어지는 것.

## 고려한 방식
| 방식 | 판단 |
|---|---|
| **job-hunter 와 같게:** 작업 브랜치 끄기와 `ignoreCommand` | **선택(사용자).** 두 저장소의 규칙이 같아집니다. 문서만 바뀌었을 때는 프로덕션 배포도 아낍니다. |
| `main` 말고 모두 끄기(`"*": false, "main": true`) | 저장소마다 규칙이 달라져서 뺐습니다. |
| Pro 플랜 | 돈이 들어서 뺐습니다. |

## 정한 것
루트 `vercel.json`:
- `git.deploymentEnabled`: `claude/*` 와 `ccr-*` 를 `false` 로 둡니다. 이전 세션들이 `ccr-…` 브랜치를 썼습니다. 따로 정하지 않은 브랜치는 기본으로 켜져 있으므로 `main` 은 계속 배포됩니다.
- `ignoreCommand`: `[ -n "$VERCEL_GIT_PREVIOUS_SHA" ] && git diff --quiet "$VERCEL_GIT_PREVIOUS_SHA" HEAD -- . <제외 경로…> || exit 1`
  - **비교 대상:** 직전 커밋(`HEAD^`)이 아니라 그 브랜치에서 마지막으로 성공한 배포(`VERCEL_GIT_PREVIOUS_SHA`)와 비교합니다(코드 리뷰 반영). `HEAD^` 와 비교하면 코드를 머지한 뒤 배포가 실패(한도·빌드 오류)했을 때 문제가 생깁니다. 다음에 문서만 바꾼 커밋이 오면 빌드를 건너뛰어, 앞서 머지한 코드가 프로덕션에 계속 배포되지 않습니다.
  - **제외 경로:** 최상위 `docs/`, 최상위 `*.md`(`glob` 이라 하위 폴더의 `.md` 는 빌드합니다), `.claude/`, `.github/`, 모든 폴더의 `*.test.mjs`.
  - **결과:**
    - 0: 제외 경로만 바뀌어 빌드를 건너뜁니다.
    - 1: 그 밖에는 모두 빌드합니다. 이전 배포 SHA 가 없거나(첫 배포) 클론에 없어 git 이 오류를 내도 빌드합니다. 확신이 없으면 배포하는 쪽을 택했습니다.

## 확인
- **로컬:** 명령을 실제 커밋과 임시 커밋에 돌려 봤습니다(구현 때 확인함).
  - 0(건너뜀): 문서만 바꾼 커밋, 최상위 `.md`·시험 파일·`.github` 만 바꾼 커밋
  - 1(빌드): 코드 변경, 코드 배포가 실패한 뒤의 문서 커밋, 이전 SHA 없음, 이전 SHA 를 모름, 하위 폴더 `.md` 변경
- **PR:** 작업 브랜치에 Vercel 배포와 `Vercel` 상태가 생기지 않는지 봅니다. `Vercel` 상태는 필수 검사가 아닙니다. #27 이 그 상태가 실패인 채로 자동 머지됐습니다.
- **머지 뒤:** `vercel.json` 이 바뀐 커밋이므로 프로덕션 배포가 정상으로 돌아야 합니다. 다음 문서 PR 이 머지될 때는 배포가 "취소됨"으로 건너뛰어지는지 봅니다.

## 남은 확인
- 건너뛴(취소된) 배포가 하루 한도에 들어가는지는 Vercel 문서에서 찾지 못했습니다.
