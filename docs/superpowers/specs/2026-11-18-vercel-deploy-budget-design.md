# Vercel 배포 한도 아끼기 설계 (작은 변경)

- 날짜: 2026-11-18
- 이슈: pdw96/Trip-Planner#29
- 상태: 승인됨 (2026-11-18)

## 의도
작업 브랜치에 push 할 때마다 Vercel 미리보기 배포가 생겨, 계정 전체에 걸리는 하루 배포 한도(무료 100회)가 금방 찹니다. 2026-11-18 에는 PR #27 의 미리보기가 한도에 걸렸습니다. 그날 계정 전체 배포 56회 가운데 42회가 미리보기였습니다.

이 앱의 미리보기로는 화면을 확인할 수 없습니다. Google 로그인 키가 없고, 미리보기 DB 에 마이그레이션도 적용하지 않습니다. 화면 확인은 로컬 dev 와 임시 테스트 계정으로 합니다(`docs/status.md`). 그래서 미리보기를 꺼도 잃는 것이 거의 없습니다.

## 목표 / 비목표
- **목표:** 작업 브랜치(`claude/*`, `ccr-*`)에서는 배포하지 않습니다. 앱과 상관없는 변경만 있으면 빌드를 건너뜁니다. `main` 의 프로덕션 배포는 그대로 둡니다.
- **비목표:**
  - job-hunter·erp 저장소 설정(다른 저장소)
  - Pro 플랜
  - CI(`check`, `human-gate`) 변경
- **반목표:** 앱 코드나 설정이 바뀌었는데 프로덕션 배포가 건너뛰어지는 것.

## 고려한 방식
| 방식 | 판단 |
|---|---|
| **job-hunter 와 같게:** 작업 브랜치 끄기와 `ignoreCommand` | **선택(사용자).** 두 저장소의 규칙이 같아집니다. 문서만 바뀌었을 때는 프로덕션 배포도 아낍니다. |
| `main` 말고 모두 끄기(`"*": false, "main": true`) | 저장소마다 규칙이 달라져서 뺐습니다. |
| Pro 플랜 | 돈이 들어서 뺐습니다. |

## 정한 것
루트 `vercel.json`:
- `git.deploymentEnabled`: `claude/*` 와 `ccr-*` 를 `false` 로 둡니다. 이전 세션들이 `ccr-…` 브랜치를 썼습니다. 따로 정하지 않은 브랜치는 기본으로 켜져 있으므로 `main` 은 계속 배포됩니다.
- `ignoreCommand`: `git diff --quiet HEAD^ HEAD -- . ` 에 아래 경로를 제외(`:(exclude)…`)로 붙입니다.
  - 제외하는 경로: `docs`, `*.md`, `.claude`, `.github`, `*.test.mjs`
  - 종료 코드에 따라 이렇게 됩니다.
    - **0:** 바뀐 것이 제외 경로뿐이라 빌드를 건너뜁니다.
    - **1:** 그 밖에 바뀐 파일이 있어 빌드합니다.
    - **그 밖의 값(git 오류):** 빌드합니다. 확신이 없으면 배포하는 쪽을 택했습니다.
  - git pathspec 의 `*` 는 `/` 도 넘어가므로 `*.md`·`*.test.mjs` 는 모든 폴더에 걸립니다. `docs` 는 저장소 최상위 `docs/` 만 뜻합니다. `src/docs/` 같은 폴더는 제외되지 않습니다.
  - `main` 은 squash 머지라 `HEAD^` 가 머지 직전의 `main` 입니다.
