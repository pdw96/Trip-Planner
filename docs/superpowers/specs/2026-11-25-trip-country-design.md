# 여행 나라 고르기와 예산 통화 처음 값 (#100)

2026-11-25. 사용자 승인(2026-11-25). 빌더 확인(서브에이전트) 반영.

## 1. 왜

사용자(2026-11-23): "여행지 입력할 때 나라 및 도시까지만 검색되게 할 수 있냐는거지. 그러면 통화설정도 간편해질거 아냐". 서울이면 원화, 도쿄면 엔화를 저절로 채우자는 생각이다.

그 뒤 #36(2026-11-25)이 이 나라 코드에 기대게 됐다. 여행 나라가 `KR` 이면 장소·이동 링크를 네이버 지도로 연다. 그래서 나라 코드는 예산 통화 처음 값뿐 아니라 여행 화면 전체에서 읽힌다.

사용자가 정한 것:

- **나라는 우리가 가진 나라 목록에서 고른다**(방법 1, 2026-11-25). Google 자동완성으로 고르고 나라를 받아 저장하는 이슈 본문의 방향은 버린다. #13 설계 §3.2 에서 지키기로 한 Google 약관이 장소의 나라를 저장 금지 값으로 두기 때문이다(`docs/superpowers/specs/2026-11-18-trip-places-map-design.md` §3.2).
- **나라 칸은 기본 고르기 목록(`<select>`)**이고, 맨 위에 자주 가는 나라를 모은다(A, 2026-11-25). 쳐서 찾는 자동완성 칸은 만들지 않는다.
- **여행지를 적으면 나라를 저절로 고른다**(ㄱ', 2026-11-25). 사용자 질문 "여행지 선택할 때 자동으로는 안돼?", "나라 및 도시 코드를 제공하는 openapi는 없어?"에서 나왔다. GeoNames 공개 데이터(CC BY 4.0)로 "한국어 도시 이름 → 나라" 표를 만들어 코드에 넣고, 실행 중에는 외부 API 를 부르지 않는다.

## 2. 목표 · 비목표 · 반목표

- 목표
  - 여행 만들기·고치기 양식에 **"나라 (선택)"** 칸. 고르지 않아도 된다(유럽 일주, 정하지 않은 여행).
  - 나라 코드(ISO 3166-1 alpha-2, 대문자 두 글자)를 여행에 저장한다.
  - 여행지 칸에 "오사카 교토", "부산", "일본 일주"처럼 적으면 나라 칸이 저절로 골라진다(§5.3.1). 못 알아보면 지금처럼 직접 고른다.
  - "예산 정하기"를 **처음 열 때**(그 여행에 예산 설정이 아직 없을 때) 나라에 맞춰 처음 값을 채운다: 예산 통화 ₩, 현지 통화, 예정 환율.
  - 기존 여행(부산 여행 포함)은 여행 고치기에서 나라를 골라 넣을 수 있다.
  - 여행 하나를 읽는 쿼리가 나라 코드를 돌려준다(#36 이 쓴다).
- 비목표
  - 도시 자동완성 목록(후보를 펼쳐 고르기), Google 장소 검색으로 여행지 고르기. 여행지 칸은 지금처럼 자유 글자다.
  - 실행 중 외부 지명 API 호출(GeoNames 웹 서비스 등). 키·한도·장애 처리가 필요해진다.
  - 표에 없는 작은 도시·지역을 알아보기.
  - 쳐서 찾는 나라 칸(콤보 박스).
  - 나라가 여럿인 여행(나라는 하나 또는 없음).
  - 이미 정한 예산 설정을 나라에 맞춰 바꾸기. 나라를 나중에 고르거나 바꿔도 예산 설정은 그대로다.
  - 기존 여행의 나라를 DB 에서 한꺼번에 채우기. 고치기 화면을 열면 양식이 짐작해 고르고(§5.3.1), 저장은 사용자가 한다.
  - 여행지·나라로 지도 처음 위치 정하기.
  - #36 의 네이버 지도 링크(이 이슈는 코드를 저장하고 읽어 주는 데까지).
- 반목표 (돌아가도 실패인 것)
  - Google 에서 받은 값(나라·주소 등)을 저장한다.
  - 기존 여행의 화면·예산 숫자가 바뀐다(나라를 고르기 전까지 지금과 똑같아야 한다).
  - 이미 예산을 정한 여행에서 나라를 바꾸면 통화·환율이 바뀐다.
  - 목록에 없는 값(소문자, 세 글자, 없는 코드)이 저장된다.
  - 환율을 받지 못하면 예산 화면이 깨지거나 늦게 뜬다(빈칸으로 두면 된다).
  - 서버와 브라우저가 다른 나라 이름을 그려 hydration 경고가 난다(§5.2).
  - 사용자가 직접 고른 나라를 자동 고르기가 덮어쓴다.
  - 여행지 낱말 일부에 우연히 걸려 엉뚱한 나라가 골라진다(예: 한 글자 지명 "빈"이 아무 낱말 속에서 걸림).
  - GeoNames 출처 표기 없이 데이터를 쓴다(CC BY 4.0 위반).
  - 여행 양식이 아닌 화면까지 지명 표(수십 KB)를 내려받는다.

## 4. 고려한 방법

**나라를 어디서 받나** (사용자가 1 을 고름)

1. **우리 나라 목록에서 고르기 — 택함.** 여행지는 자유 글자, 나라는 따로 고른다. Google 호출 없음, 약관 문제 없음. Google 후보가 없는 "규슈"도 일본을 고르면 된다. 도시 자동완성은 없고 칸이 하나 는다.
2. Google 자동완성으로 고르면 나라 칸을 미리 채우고 사용자가 확인한 값을 저장. 한 번에 끝나지만 §3.2 가 금지한 나라를 사실상 저장하는 셈이라 애매하다.
3. 여행지의 Google 장소 id 만 저장하고 나라는 볼 때마다 Place Details 로 받기. 약관에는 맞지만 #36 때문에 여행 화면을 열 때마다 Google 을 부르고(비용), 실패하면 네이버 링크가 사라진다.

**나라 칸 모양** (사용자가 A 를 고름)

- **A. 기본 `<select>` + 맨 위 "자주 가는 나라" 묶음 — 택함.** 휴대폰은 기기 고르기 화면, 화면 읽기·키보드는 기본 지원, 코드가 짧다. 먼 나라는 스크롤이 길다.
- B. 쳐서 찾는 자동완성 칸. "검색" 느낌에 가깝지만 방향키·화면 읽기 처리를 직접 만들어야 해서 코드·시험이 크게 는다.

**여행지로 나라를 저절로 고르기** (사용자가 ㄱ' 를 고름)

- ㄱ. 손으로 만든 "도시 → 나라" 표(200곳 안팎). 외부 의존 없음, 표 관리가 손일이고 범위가 좁다.
- **ㄱ'. GeoNames 데이터 파일로 만든 표 — 택함.** `cities15000`(인구 1만 5천 이상 도시 34,246곳) 중 한국어 이름이 있는 6,154곳으로 표를 만든다. 실행 중 호출 없음. 출처 표기 필요(CC BY 4.0).
- ㄴ'. GeoNames 웹 서비스를 실시간으로 부르기. 작은 도시까지 되지만 사용자명(키)·Vercel 환경 변수·`.env.example`(위험 경로)·서버 호출·장애 처리가 는다. 무료 한도 하루 1만 회.

## 5. 설계

### 5.1 DB

`trips` 에 비어도 되는 칸 하나:

```ts
// 여행 나라(#100). ISO 3166-1 alpha-2 대문자. 사용자가 우리 목록에서 고른 값이다(Google 값 아님). null = 고르지 않음.
countryCode: text("country_code"),
```

검사 제약 `trips_country_code_check`: `country_code IS NULL OR country_code ~ '^[A-Z]{2}$'`. 어떤 코드가 "있는 나라"인지는 앱(§5.2 목록)이 정하고, DB 는 모양만 막는다(목록이 바뀔 때마다 마이그레이션하지 않으려고. Claude 판단).

예상 SQL(생성 결과로 확인):

```sql
ALTER TABLE "trips" ADD COLUMN "country_code" text;
ALTER TABLE "trips" ADD CONSTRAINT "trips_country_code_check" CHECK ("trips"."country_code" IS NULL OR "trips"."country_code" ~ '^[A-Z]{2}$');
```

파괴적이지 않다(새 칸은 비어도 되고 기존 행은 모두 null, 새 제약은 null 을 통과).

**옛 코드와 새 DB** (`CLAUDE.md` '마이그레이션 PR'):

1. 적용부터 새 배포 READY 까지: **안전.** 옛 코드는 칸을 모른다. 여행 만들기는 null 로 들어가고, 고치기(`updateTrip` 의 `.set(input)`)는 이 칸을 건드리지 않는다. 읽기는 칸 목록을 적어 읽으므로 영향 없음.
2. 그 뒤 옛 배포로 되돌릴 때: **안전.** 옛 코드는 나라를 보이지 않고 쓰지도 않는다. 나라가 막는 것(권한 등)이 없어 보안·데이터 손상이 없다. 롤백 금지선 아님.

### 5.2 나라 목록 (`src/lib/countries.ts`, 순수 모듈)

- `COUNTRY_CODES`: ISO 3166-1 alpha-2 에 정식으로 배정된 코드 전부(249개). 목록을 코드에 적는다(`Intl` 에 나라 목록을 주는 표준 기능은 없다).
- `FREQUENT_COUNTRY_CODES`: 자주 가는 나라, 이 순서대로(Claude 판단, 한국인 출국 많은 곳 기준): `KR`(대한민국), `JP`, `VN`, `CN`, `TH`, `PH`, `TW`, `US`, `GU`(괌), `HK`, `SG`, `MY`, `ID`. 모두 `COUNTRY_CODES` 안에 있어야 한다(시험).
- `COUNTRY_CURRENCY`: 나라 → 통화. **지원 통화 18개(`src/lib/budget.ts` 의 `CURRENCIES`)를 법정 통화로 쓰는 나라만** 적는다. 없으면 통화 처음 값 없음. 시작 표(구현자가 원문으로 한 번 더 확인):
  - KRW: KR · JPY: JP · CNY: CN · HKD: HK · TWD: TW · THB: TH · VND: VN · SGD: SG · PHP: PH · MYR: MY · IDR: ID · CAD: CA
  - USD: US, GU, MP, AS, PR, VI, EC, SV, TL, FM, MH, PW, BQ, TC, VG
  - EUR: 유로존 21개국(2026-01-01 불가리아 가입 반영: AT BE BG CY DE EE ES FI FR GR HR IE IT LT LU LV MT NL PT SI SK) + 유로를 쓰는 비유로존(AD MC SM VA ME) + 프랑스 해외 지역(GF GP MQ YT RE BL MF PM)
  - GBP: GB, IM, JE, GG · AUD: AU, KI, NR, TV, CX, CC, NF · CHF: CH, LI
  - XK(코소보)는 ISO 정식 배정 코드가 아니라 `COUNTRY_CODES` 에 없으므로 넣지 않는다.
  - `COUNTRY_CURRENCY` 의 모든 키는 `COUNTRY_CODES` 안에 있어야 한다(시험). 값이 `CURRENCIES` 안에 있는지는 순수 모듈끼리 import 하지 않으므로 통화 코드 문자열 집합을 이 파일에 따로 두지 않고, 부르는 쪽(서버)에서 `currencyInfo()` 로 한 번 더 거른다.
- `isCountryCode(value)`: `COUNTRY_CODES` 에 있는가.

**나라 이름**: `new Intl.DisplayNames(["ko"], { type: "region" }).of(code)` (Node·브라우저 기본 기능, 새 패키지 없음. 2026-11-25 확인: 대한민국·일본·대만·괌·마카오(중국 특별행정구)). **이름과 가나다 정렬(`localeCompare(…, "ko")`)은 서버에서 만들어** 양식(클라이언트 컴포넌트)에 `{ code, name }[]` 로 넘긴다. 브라우저에서 만들면 Node 와 브라우저의 ICU 차이로 이름이 달라 hydration 경고가 날 수 있다(반목표). `Intl.DisplayNames` 가 이름을 모르면 코드를 그대로 돌려주는데, 그 값도 그대로 쓴다.

### 5.3 양식

`trip-form.tsx`: "여행지" 칸 바로 아래에 "나라 (선택)":

```
나라 (선택)
[ 선택 안 함            ▾]
  ── 자주 가는 나라 ──        ← <optgroup label="자주 가는 나라">
  대한민국 · 일본 · 베트남 …
  ── 전체 ──                  ← <optgroup label="전체 (가나다순)">
  가나 · 가봉 · 가이아나 …
```

- 첫 option `value=""` "선택 안 함".
- 자주 가는 나라는 "전체"에도 한 번 더 나온다(가나다로 찾는 사람이 못 찾지 않게. Claude 판단). 같은 value 가 둘이어도 `<select>` 는 값이 같아 문제없다.
- 아래 작은 안내 한 줄(Claude 판단): "예산을 처음 정할 때 현지 통화와 환율을 미리 채워요." — 왜 고르는지 알려 준다. 만들기·고치기 모두 같은 문구다(이미 예산이 있는 여행에는 "처음 정할 때"가 해당하지 않음이 문구로 드러나므로 고치기 화면에서 예산 설정을 읽지 않는다).
- `name="countryCode"`. 기존 `Field` 를 쓴다. 오류는 다른 칸처럼 아래에 보인다.
- `TripFields`·`TripInput`·`EMPTY_TRIP_FIELDS` 에 `countryCode` 를 더한다(`TripFields` 는 문자열, `TripInput` 은 `string | null`).
- 고치기 화면(`src/app/trips/[id]/edit/page.tsx`)은 지금 값(`trip.countryCode ?? ""`)으로 채운다.
- 여행 목록·자세히 보기 머리에는 나라를 보이지 않는다(Claude 판단: 여행지 글자로 충분하고, 고른 값은 고치기 화면에서 보인다).

#### 5.3.1 여행지로 나라 저절로 고르기

여행지 칸에 글자를 칠 때마다(브라우저에서) 지명 표(§5.3.2)와 나라 이름으로 나라를 짐작해 나라 칸을 고른다.

```
여행지
[ 오사카 교토                     ]

나라 (선택)
[ 일본                          ▾ ]
여행지를 보고 골랐어요. 다르면 바꿔 주세요.
예산을 처음 정할 때 현지 통화와 환율을 미리 채워요.
지명 데이터: GeoNames (CC BY 4.0)
```

**짐작하는 법** (순수 함수, `src/lib/place-match.ts` 같은 곳. 표는 인자로 받는다):

1. 여행지를 낱말로 나눈다(빈칸, `,` `·` `/` `(` `)` `-` `~` 등).
2. 낱말마다 그대로, 그리고 끝말을 뗀 것으로 표를 찾는다. 뗄 끝말(긴 것부터): `특별자치도` `특별자치시` `특별시` `광역시` `여행` `시` `도` `섬`. 뗀 뒤 두 글자 이상일 때만 뗀다. 예: "부산여행" → "부산", "제주도" → "제주", "오사카시" → "오사카".
3. **낱말과 표 이름이 통째로 같을 때만** 맞는다(낱말 속 일부는 보지 않는다). "빈"(빈, 오스트리아)이 "빈티지"에 걸리지 않게 한다(반목표).
4. 찾은 나라가 **하나뿐이면** 그 나라. 없거나 둘 이상이면("서울 도쿄") 짐작하지 않는다.

**언제 고르나**:

- 나라 칸을 사용자가 **직접 바꾸기 전까지만** 여행지를 따른다. 짐작이 맞으면 그 나라, 짐작하지 못하면 "선택 안 함"으로 돌아간다(앞서 저절로 고른 값이 남아 엉뚱해지지 않게). 사용자가 나라 칸을 한 번이라도 바꾸면 그 양식에서는 다시 건드리지 않는다.
- 양식이 열릴 때 나라 값이 이미 있으면(고치기, 또는 서버 검증 오류로 돌아온 값) 사용자가 고른 것으로 보고 건드리지 않는다.
- 양식이 열릴 때 나라가 비어 있고 여행지가 있으면(나라 없는 기존 여행의 고치기 화면) **바로 한 번 짐작한다.** 부산 여행은 고치기를 열면 대한민국이 골라져 있고, 저장하면 들어간다. 저장 전에는 DB 에 쓰지 않는다.
- 저절로 골랐을 때만 "여행지를 보고 골랐어요. 다르면 바꿔 주세요." 한 줄(Claude 판단).
- 지명 표를 아직 못 받았으면(불러오는 중·실패) 짐작하지 않고 직접 고르기만 된다. 표를 받으면 그때의 여행지로 한 번 짐작한다(위 조건대로).

나라 칸은 짐작 때문에 제어 컴포넌트(`value` + 상태)가 된다. 이름 `countryCode` 로 폼에 실리는 것은 같다.

#### 5.3.2 지명 표 (GeoNames)

- 출처: GeoNames `cities15000.zip`(https://download.geonames.org/export/dump/, 인구 1만 5천 이상 도시). CC BY 4.0. 2026-11-25 받은 파일: 34,246곳, 그중 다른 이름(`alternatenames`) 칸에 한글 이름이 있는 곳 6,154곳.
  - 이 파일의 다른 이름 칸에는 언어 표시가 없다. **한글로만 된 이름**(가–힣과 빈칸)을 한국어 이름으로 본다.
  - 일본 도시는 "오사카 시", "교토 시"처럼 "시"가 붙어 있다. 표에는 빈칸을 뺀 이름(`오사카시`)과 끝의 "시"를 뗀 이름(`오사카`, 두 글자 이상일 때)을 함께 넣는다.
  - 같은 이름이 여러 나라에 있으면(101개, 예: 런던 GB/CA, 시드니 AU/CA, 바르셀로나 ES/VE) **인구가 가장 많은 도시의 나라**로 정한다.
- 손으로 더하는 지역·섬(Claude 판단, 구현자가 늘려도 됨): 도시 파일에 없는 여행지. 규슈·홋카이도·오키나와·혼슈·시코쿠(JP), 하와이(US), 사이판(MP), 발리·롬복(ID), 보라카이·보홀·팔라완(PH), 푸꾸옥·푸꼭(VN), 푸껫·코사무이(TH), 제주도(KR, 끝말 떼기로도 됨) 등. 2026-11-25 확인: 오사카·교토·후쿠오카·삿포로·나하는 "시"를 떼면 찾아지고, 괌은 나라 이름(GU)으로 찾아진다.
- 나라 이름도 찾는다: §5.2 의 한국어 나라 이름(`Intl.DisplayNames`, 서버가 만들어 양식에 넘기는 그 목록). "일본 일주" → 일본. 나라 이름과 도시 이름이 같으면 나라 이름이 이긴다(예: 싱가포르·홍콩은 어느 쪽이든 같다).
- **만드는 법**: 저장소에 스크립트(예: `scripts/build-place-names.mjs`)를 두고, 내려받은 `cities15000.txt` 경로를 인자로 받아 표 파일(예: `src/lib/place-names.ts`, `{ [이름]: 나라코드 }`)을 만든다. 손으로 더하는 목록은 스크립트 쪽 소스에 둔다. 만든 파일 맨 위에 "만든 파일 — 손으로 고치지 않음, 출처 GeoNames CC BY 4.0, 받은 날짜, 다시 만드는 명령"을 적는다. 내려받은 원본(8.5MB)은 커밋하지 않는다.
- 표의 나라 코드는 모두 §5.2 `COUNTRY_CODES` 안에 있어야 한다(시험. 없는 코드의 줄은 스크립트가 버린다).
- 크기: 약 6,800 이름, 132KB(gzip 약 40KB). **여행 양식에서만** 동적 import(`import()`)로 따로 받는다(반목표: 다른 화면에 싣지 않음). 줄일 필요가 생기면 인구 하한을 올린다(5만 이상이면 4,604 이름·27KB).
- 출처 표기: 나라 칸 아래 작은 글자 "지명 데이터: GeoNames (CC BY 4.0)", GeoNames 와 라이선스 링크(Claude 판단: 데이터를 쓰는 바로 그 자리).
- Biome 이 큰 만든 파일을 검사·포맷하느라 느리거나 시끄러우면 `biome.json` 에서 그 파일을 뺀다(위험 경로라 `human-approved` 가 필요. 같은 PR 의 승인으로 함께 받는다). 빼지 않아도 되면 건드리지 않는다.

### 5.4 검증과 저장

- `parseTripInput`(`src/lib/trip-input.ts`): `countryCode` 를 trim. 빈칸 → `null`. 아니면 `isCountryCode` 여야 한다. 아니면 필드 오류 "나라를 목록에서 다시 골라 주세요." `trip-input.ts` 는 순수 모듈이라 `countries.ts` 를 import 하지 않는다 → **검사 함수를 인자로 받는다**(`budget-input.ts` 가 `moneyParsers` 를 받는 방식과 같다. 구현자가 시그니처를 정한다).
- `readTripFields`(`src/app/trips/actions.ts`)에 필드 하나 더. 만들기·고치기 모두.
- `createTrip`·`updateTrip`: `TripInput` 을 그대로 `.values()`/`.set()` 하므로 칸이 들어가면 함께 저장된다. 고치기 권한은 지금과 같다(`accessibleTrips`, 여행지를 고칠 수 있는 사람은 나라도 고친다).
- `getTrip` 이 `countryCode` 를 돌려준다(#36 용).

### 5.5 예산 처음 값

언제: 여행 화면에서 그 여행의 예산 설정(`config`)이 **없고**, 여행 나라가 있을 때만. 설정이 있으면 지금과 똑같다(`settingsFields(config)`).

무엇을:

| 칸 | 처음 값 |
|---|---|
| 예산 통화 | 늘 KRW(지금 처음 값과 같음. 사용자 대부분 한국 출발. Claude 판단) |
| 현지 통화 | `COUNTRY_CURRENCY[나라]` 가 있고, `currencyInfo()` 로 지원 통화이고, KRW 가 아니면 그 통화. 아니면 "없음" |
| 예정 환율 | 현지 통화가 채워졌고 그 통화가 기준환율 출처에 있으면(`ecb: true`) **최근 기준환율**. 없으면(TWD·VND 등) 빈칸 |
| 방식·총 예산·내 예산 | 지금 처음 값 그대로 |

- 최근 기준환율: 서버가 `getEcbRate(todayInSeoul(), 현지통화, "KRW")` 로 받는다(Frankfurter 는 그날 값이 없으면 직전 영업일 값을 준다. 2026-11-25 에 물으면 11-24 값이 왔고, `cacheLife("max")` 라 그날 내내 그 값이 남는다). 결과를 양식 칸의 단위(`rateUnit`, 엔은 100엔당)로 바꿔 문자열로 넣는다(`rateInputValue` 와 같은 표기). 실패(null)면 빈칸. 받는 동안 예산 영역을 늦추지 않도록 구현자가 자리를 정한다(예: 예산 데이터와 함께 Promise 로 받기). 오늘 값이 캐시에 오래 남을 수 있는 것은 #14 남은 지적과 같고 처음 값일 뿐이라 받아들인다.
- 환율 방향·단위는 실제 지출의 `resolveActualRate` 가 쓰는 것과 같아야 한다(구현자가 맞춰 보고 단위 시험으로 지킨다).
- 처음 값을 정하는 부분은 순수 함수로 둔다: `(countryCode, rate | null) → { localCurrency, plannedRate }` 에 가깝게. 통화 지원 여부는 인자로 받거나 부르는 쪽에서 거른다(순수 모듈 규칙).
- 이 값은 양식의 처음 값일 뿐이다. 사용자가 저장하기 전에는 DB 에 아무것도 쓰지 않는다. 사용자가 바꿀 수 있다.
- 설정이 없을 때의 양식(`<BudgetSettingsForm config={null}>`)은 `budget-card.tsx` 의 `CardsBody` 한 곳에서 그린다. 빈 예산 카드의 "예산 정하기"와 아래 판(`BudgetSetupDock`)의 "예산 정하기"가 모두 이리로 온다. 처음 값은 `BudgetSection → BudgetArea → BudgetSheet → BudgetCards → BudgetSettingsForm` 으로 내려준다(구현자가 더 짧은 길을 찾으면 그쪽). "내 예산 정하기"·"모임 예산 정하기"는 설정이 늘 있어 해당 없다.
- **예산 통화를 바꾸면 환율 칸을 비운다**(빌더 확인에서 나옴, Claude 판단). 지금 양식은 환율 칸이 현지 통화로만 `key` 가 걸려 있어, 일본 여행에서 미리 채운 "100엔 = 845.23원"을 둔 채 예산 통화를 달러로 바꾸면 "100엔 = 845.23달러"로 저장된다. 사용자가 적지 않은 값이 조용히 합계를 부풀린다. 그래서 환율 칸의 `key` 와 처음 값 조건에 예산 통화도 넣는다(현지·예산 통화가 둘 다 처음과 같을 때만 처음 값, 아니면 빈칸). 이미 예산을 정한 여행에도 같이 적용되며 더 안전한 쪽으로만 바뀐다(예산 통화를 바꿨다 되돌리면 저장된 값이 다시 보인다).
