# 전체 화면 디자인 정리: 노선도 (#53)

2026-11-20. 초안(사용자 승인 전). 시안: 디자인 방향 https://claude.ai/artifact/9WdXd5NFaMih8i1hKEBCYg , 날짜 탭 비교 https://claude.ai/artifact/LetFNVKL85toT6M6XZxSBe (사용자 비공개 페이지)

## 1. 왜

기능별로 붙여 온 화면이 Next 시작 템플릿 모양(회색·검정, 둥근 테두리)을 그대로 쓰고 있다. 사용자는 화면을 **여행 컨셉에 맞는 디자인**으로 만들고 싶다(사용자: "디자인적으로 여행 컨셉에 맞게"). 칸 배치를 새로 짜는 일보다 모양이 먼저다(사용자: "그런 것보단 디자인적으로").

같이 해결할 것: 화면마다 색·테두리·오류 문구를 따로 적어 와서 생긴 문제(#52: 공용 `inputClass` 의 `w-full` 이 다른 폭을 이겨 금액 칸이 0 폭), 그리고 `layout.tsx` 가 Geist 글꼴을 불러 놓고 `globals.css` 의 `body { font-family: Arial }` 이 덮어써 실제로는 기기 기본 글꼴로 보이는 것(Geist 에는 한글도 없다).

## 2. 고른 방향

시안 페이지(claude.ai 비공개 Artifact, 2026-11-20)에서 세 방향(A 탑승권, B 노선도, C 여행 수첩)을 보였다. 사용자가 **B 노선도에 예산은 A 처럼**을 골랐고, 앱 전체로 이어 그린 두 번째 시안(여행 목록, 여행 화면 밝게·어둡게, 양식·버튼, 날짜 색)에 "좋네".

- **노선도**: 여행의 하루가 지하철 노선 하나다. 날마다 노선 색이 있고, 일정은 역, 일정 사이 이동 시간은 역 사이 구간이다. 이 앱만의 기능(동선·이동 시간)이 화면의 얼굴이 된다.
- **예산(A)**: 한 장짜리 카드에 "예상 472,000 / 600,000원" 과 가로 막대 하나. 남으면 초록 "여유", 넘으면 막대와 문구가 빨강.

## 3. 목표 · 비목표 · 반목표

- 목표
  - 모든 화면(홈·여행 목록·여행 만들기·고치기·여행 화면·초대·오류/없음 화면)이 같은 노선도 디자인을 따른다.
  - 색·글꼴을 한 곳(토큰)에 모아, 다크 모드와 색 변경을 한 곳에서 한다.
  - 버튼·입력칸·카드·오류 문구·빈 상태를 공용 조각으로 맞춘다. 입력칸 폭 규칙이 #52 같은 충돌을 다시 만들지 않는다.
  - 한글이 있는 글꼴(IBM Plex Sans KR)이 실제로 쓰인다.
- 비목표
  - 데이터·마이그레이션 변경. 동작(저장·권한·순서 규칙·이동 시간 묻는 방식)은 그대로다. 바뀌는 동작은 하나: 날짜 고르기가 일정까지 거른다(§5.4.1, 사용자 선택).
  - 칸 배치 대개편. 여행 화면 칸 순서는 지금과 거의 같다(§5.4).
  - 새 기능(#36 경로 후보, #23 달력 키보드 등). 이 틀이 생긴 뒤 넣는다.
  - 다크 모드 수동 전환 버튼. 지금처럼 기기 설정을 따른다.
- 반목표 (돌아가도 실패인 것)
  - 디자인을 바꾸다 기존 동작이 깨진다: 일정 끌어 옮기기(마우스·터치·키보드), 완료 체크와 실제 지출 칸, 그 자리 고치기, 이동 시간 줄, 지도 탭·핀·동선, 초대·참여.
  - 노선 색이 조작 색처럼 보여 화면이 알록달록해진다(버튼·링크는 늘 잉크색 하나).
  - 다크 모드에서 읽기 어려운 글자·안 보이는 입력칸이 생긴다(#44 같은 것).
  - 휴대폰 너비(360px)에서 가로 스크롤이나 잘린 글자가 생긴다.
  - 새 패키지·위험 경로(`package.json`, `next.config.ts` 등)를 건드려 사람 승인 게이트가 필요해진다.

## 4. 방법 (Claude 가 정함, 사용자 위임)

사용자는 만드는 방법을 Claude 에게 맡겼다("무슨 말인지 몰라" → 쉬운 말로 설명, 이의 없음).

| | 방법 | 장점 | 단점 |
|---|---|---|---|
| **1** | **토큰 + 공용 클래스·작은 컴포넌트.** `globals.css` 의 Tailwind `@theme` 에 색·글꼴 토큰, `styles.ts` 를 넓히고, 반복 그림(날짜 동그라미·노선·예산 막대)만 컴포넌트로 | 지금 방식(Server Component + 클래스 문자열)을 그대로 따른다. 새 패키지 없음, 위험 경로 없음 | 폭 실수를 타입으로 막지는 못한다(클래스 규칙으로 막는다, §5.3) |
| 2 | 버튼·입력칸을 모두 React 컴포넌트로 감싸기 | 폭 등을 prop 으로 강제 | `Link`·`button`·양식 안 버튼이 같은 모양을 나눠 써서 감쌀 경우가 많고, 바뀌는 범위가 훨씬 넓다 |
| — | UI 라이브러리(shadcn·Radix) | — | 새 패키지(위험 경로), 어차피 노선도 모양으로 다시 칠해야 해 뺐다 |

내보내기는 **PR 두 번**(Claude 판단, 사용자에게 알림): 파일이 30개 가까이라 한 번에 리뷰·확인하기 어렵다.

1. **PR 1 — 바탕**: 토큰·글꼴·공용 조각, 홈·여행 목록·여행 만들기/고치기·초대·오류 화면. `Refs #53`.
2. **PR 2 — 여행 화면**: 머리·함께하는 사람, 날짜 고르기, 지도 선·핀 색, 예산 카드, 노선 일정, 가 볼 곳, 양식들. `Closes #53`.

각 PR 은 따로 배포되어 사용자가 써 볼 수 있다. PR 1 만 나간 상태에서도 여행 화면이 깨지지 않아야 한다. PR 1 은 공용 버튼·입력칸 상수의 **모든 사용처**(여행 화면 파일 포함)를 새 클래스로 바꾼다. 옛 상수(`inputClass` 등)를 남기지 않는다. 그래서 PR 1 배포 동안 여행 화면은 버튼·입력칸·글꼴·색 토큰만 새 모양이고, 배치·노선·예산 카드는 옛 모양이다(Claude 판단: 옛 상수를 남기면 #52 충돌이 PR 2 까지 살아 있다).

## 5. 설계

### 5.1 토큰 (`src/app/globals.css`)

Tailwind 4 `@theme` 로 색 토큰을 정의해 `bg-surface`·`text-sub` 같은 유틸리티를 만든다. 값은 CSS 변수로 두고, 다크 모드는 `@media (prefers-color-scheme: dark)` 에서 변수만 바꾼다. 컴포넌트에는 `dark:` 클래스를 쓰지 않는다(노선 색 대비처럼 꼭 필요한 곳 제외).

| 토큰 | 밝게 | 어둡게 | 쓰임 |
|---|---|---|---|
| `background` | `#ffffff` | `#121418` | 바탕 |
| `surface` | `#f3f4f7` | `#1c1f25` | 카드·양식 판·지도 자리 |
| `ink` (`foreground`) | `#1b1d21` | `#eceef2` | 글자, 주 버튼 바탕, 링크 |
| `on-ink` | `#ffffff` | `#121418` | 주 버튼 글자 |
| `sub` | `#6a707b` | `#9aa1ad` | 보조 글자(지금 `zinc-500/600`) |
| `rule` | `#e6e8ed` | `#2b2f37` | 구분선 |
| `field` / `field-line` | `#ffffff` / `#cfd3da` | `#16181d` / `#3a3f49` | 입력칸 바탕·테두리, 보조 버튼 테두리 |
| `danger` | `#c8322f` | `#f06a65` | 오류 문구, 위험 버튼, 예산 초과, 일요일·공휴일 |
| `ok` | `#1d7f45` | `#4cc27c` | 예산 여유 |
| `line-1`…`line-8` | `#1f9a52 #ef7d1a #2a6fd6 #8a4fd0 #0e97a8 #d6336c #9a7420 #5a6b8c` | `#33b46a #f39234 #4b8ef0 #a273e6 #25b3c4 #ea5a8c #c39a3c #7d8fb3` | 날짜(노선) 색 |

- 기존 `--background`·`--foreground` 이름은 유지한다(이미 `bg-foreground text-background` 를 쓰는 곳이 있다). `ink` 는 `foreground` 의 별칭이어도 된다(빌더 판단).
- `color-scheme: light dark` 는 그대로 둔다(#44).
- 정확한 hex 는 대비(본문 4.5:1, 노선 동그라미 안 숫자 3:1 이상)를 확인하며 빌더가 조금 고쳐도 된다.

### 5.2 글꼴 (`src/app/layout.tsx`, `globals.css`)

- `next/font/google` 으로 **IBM Plex Sans KR**(400·500·600·700)을 불러 `--font-sans` 로 쓴다. Geist·Geist Mono 는 뺀다.
- `globals.css` 의 `body { font-family: Arial, … }` 을 지운다(토큰의 `--font-sans` 가 이긴다).
- 숫자가 줄 맞춤되는 곳(시각, 금액, 표)은 `tabular-nums`.
- 한글 글꼴은 커서 `next/font` 가 하위 집합을 나눠 받는지, 첫 화면 글자 깜빡임(FOUT)이 괜찮은지 빌드·브라우저로 본다. `next/font/google` 의 한글 글꼴 처리(subsets, preload)는 `node_modules/next/dist/docs/` 를 먼저 읽고 정한다(빌더).

### 5.3 공용 조각 (`src/app/trips/styles.ts` 를 `src/app/ui/` 로 옮기거나 넓힘)

홈·초대 화면도 쓰므로 `src/app/trips/` 밖(예: `src/app/ui/styles.ts`)으로 옮긴다(빌더 판단, 옮기면 import 를 모두 고친다).

- **버튼**: 높이 40px(작은 것 32px), 모서리 10px. `primary`(잉크 바탕), `secondary`(테두리), `danger`(빨강 테두리·글자), `quiet`(테두리 없는 글자 버튼: "일정 넣기", "취소" 같은 곳). 지금의 `rounded-full` 알약 모양은 버린다. 터치 영역은 최소 40px.
- **입력칸**: 높이 42px, 모서리 10px, `field`·`field-line`, 초점 링은 잉크색(노선 색 아님), `aria-invalid` 면 `danger` 테두리.
  - **폭 규칙**: 입력칸 기본 클래스에는 **폭을 넣지 않는다**. 폭은 쓰는 쪽이 늘 붙인다(`w-full`, `w-32`, `flex-1`). `inputClass = w-full + base` 같은 합친 상수를 없애 #52 충돌을 원천적으로 막는다. `trip-map-panel.tsx` 의 `selectClass` 도 이 규칙으로.
- **카드**: `surface` 바탕, 모서리 14px, 테두리·그림자 없음. 카드는 예산·양식 판·빈 상태처럼 따로 떼어 보일 것에만. 여행 목록·장소 목록·일정은 카드가 아니라 구분선 줄이다.
- **오류 문구**: `danger`, 13px, 칸 바로 아래 한 줄, `role="alert"`. 지금 32곳의 `text-red-600` 을 공용 클래스로.
- **빈 상태**: 점선 테두리 판 + 안내 한 줄 + (있으면) 할 일 버튼 하나. 문구는 "아직 … 없어요. …하면 …돼요." 꼴.
- **칸 제목**: `h2` 는 18px 700, 작은 구획 제목은 13px 600 `sub` 색. 대문자·눈썹 글씨 없음.

### 5.4 화면별

공통: 본문 폭 `max-w-2xl` 한 단 유지, 좌우 여백 16px(휴대폰) / 24px(sm 이상).

**홈 (`/`)**: 앱 이름과 한 줄 소개, Google 로그인 버튼. 노선 모양 장식 하나(3일짜리 짧은 노선 그림 정도)는 빌더 판단. 앱 안 브라우저 안내는 그대로.

**여행 목록 (`/trips`)**
- 여행 하나 = 구분선 사이 한 줄: 제목(17px 700), "목적지, 기간 · N일 남음" 보조 글자, 그 아래 **날 수만큼 역이 찍힌 짧은 노선**(동그라미 테두리 색 = 그날 노선 색). 날이 많으면 동그라미가 줄 폭을 넘지 않게 줄인다(예: 14일 넘으면 처음 몇 개 + "…" 또는 동그라미 크기 축소, 빌더 판단).
- 지난 여행은 제목·노선을 흐리게. 공유받은 여행은 제목 옆 작은 테두리 표시 "○○님의 여행".
- "N일 남음"은 다가오는 여행만(오늘이 여행 중이면 "여행 중", 빌더가 `trip-dates.ts` 에 순수 함수로).

**여행 만들기·고치기**: 공용 입력칸·버튼으로. 날짜 범위 달력은 선택 범위 색을 잉크색으로, 일요일·공휴일은 `danger`.

**초대 (`/invite/...`)·오류·없음 화면**: 공용 조각으로 색만 맞춘다.

**여행 화면 (`/trips/[id]`)** — 위에서부터:
1. 위 줄: "← 내 여행" 과 [고치기]·[삭제](주인만) 작은 버튼.
2. 제목(24px 700), "목적지, 날짜부터 N박 M일", 메모(있으면 `surface` 판).
3. **함께하는 사람**: 기본은 겹친 동그라미 사진 + 이름들 한 줄. 눌러서 펼치면 지금의 목록·내보내기·나가기·초대 링크 칸(주인). (Claude 제안: 지금 칸이 위쪽을 많이 차지한다.)
4. **지도 칸** (`trip-map-panel.tsx`):
   - 날짜 고르기(§5.4.1): [전체] 알약 + **날짜 동그라미**(N일차 숫자, 바탕 = 노선 색, 고르지 않은 날은 흐리게, 고른 날은 바깥 고리). 고른 날 옆에 "12월 5일 토" 글자. 날이 많으면 가로 스크롤(지금과 같음). 동그라미는 `button aria-pressed` 그대로, 이름은 "1일차 12월 5일 토".
   - 예산 카드(§5.5) → 지도 → 기준점 고르기 → 구간 목록, 순서는 지금과 같다.
   - 지도: N일차 동선 선과 번호 핀 색 = 그날 노선 색(지금 `#2563eb`·`bg-blue-600` 고정). [전체] 탭의 핀은 잉크색 또는 그 장소가 들어간 첫날 색(빌더 판단, 장소 핀은 일정 날이 여럿일 수 있음).
   - 구간 목록(`day-legs.tsx`)은 일정표의 이동 줄과 같은 글자 모양(노선 색 글자 "지하철 22분" + "길찾기" 링크).
5. **가 볼 곳**: 구분선 줄 목록, 종류 이모지는 유지, 빈 상태는 §5.3.
6. **일정** (`schedule-section.tsx`, `schedule-day-items.tsx`, `schedule-editor.tsx`):
   - 보이는 날은 날짜 고르기를 따른다(§5.4.1): [전체] 면 모든 날, N일차면 그날만.
   - 날마다 머리: 날짜 동그라미 + "12월 5일 토" + 오늘이면 "오늘" 표시. "오늘 일정으로 ↓" 링크는 없앤다(여행 중이면 처음부터 오늘이 골라져 있다).
   - 그날 일정은 **노선**: 왼쪽 시각 칸(15px 700, 시각 없으면 "시각 없음" 작은 보조 글자), 가운데 세로 선(6px, 노선 색)과 역 동그라미, 오른쪽 제목·장소·메모. 선은 첫 역에서 시작해 마지막 역에서 끝난다.
   - **역 동그라미 = 완료 체크칸**(Claude 제안): 빈 동그라미 = 안 함, 노선 색으로 채움 = 완료. 실제로는 지금의 체크칸(`input type=checkbox`)을 동그라미 모양으로 꾸민 것이라 동작·키보드·스크린리더는 그대로다. 터치 영역 40px. 완료 일정 글자는 보조 색(취소선은 빼도 됨, 빌더 판단).
   - 끄는 손잡이 ⠿ 는 줄 오른쪽 끝으로 옮긴다(체크칸이 있던 자리). 끄는 중 모양(떠오른 줄)은 `surface` 바탕.
   - 이동 줄: 역 사이 선 옆에 노선 색 글자 "지하철 22분" + 보조 색 "길찾기" 링크, 실패면 "다시". 끄는 동안 숨김은 그대로.
   - 일정이 없는 날: 선 없이 "아직 일정이 없어요" + 일정 넣기.
   - "일정 넣기": 점선 동그라미 + 글자(노선 끝에 붙는 역처럼).
   - 그 자리 고치기 양식·실제 지출 칸: 공용 입력칸·버튼으로, 양식 판은 `surface`.
   - 여행 기간 밖 일정: 회색 노선(`sub` 색)으로, 지금처럼 맨 아래 따로. [전체] 일 때만 보인다.

#### 5.4.1 날짜 고르기가 지도·예산·일정을 함께 바꾼다 (사용자: 나)

비교 시안(가: 지도·예산만 / 나: 일정까지)에서 사용자가 **나**를 골랐다.

- 고른 값: `"all"` 또는 날짜. 처음 값은 지금 지도 탭과 같다(여행 중이면 오늘, 아니면 [전체]). 페이지 안 상태로만 두고 주소·DB 에 저장하지 않는다(지금 지도 탭과 같음).
- [전체]: 지도는 모든 장소 핀, 예산은 여행 전체 카드, 일정은 모든 날 + 기간 밖 일정. 지금 화면과 같다.
- N일차: 지도는 그날 노선, 예산은 그날 카드, 일정은 **그날 하나만**. 가 볼 곳 칸은 날짜와 상관없이 그대로(지금처럼 [전체] 의 "가까운 순 기준" 정렬만 따른다).
- 지금 고른 탭은 `trip-map-panel.tsx` 안 `useState` 이고, 일정 칸(`schedule-section.tsx`, 서버)은 따로 그려진다. 두 칸을 이미 감싸는 페이지 저장소(`day-route-store.tsx` 의 `DayRouteProvider`) 옆에 고른 날 저장소(클라이언트 context)를 두고, 지도 칸과 일정 칸이 같이 읽는다(빌더가 같은 provider 에 넣을지 따로 둘지 정함).
- 일정 칸의 숨긴 날은 **그리되 감춘다**(`hidden`). 날마다 끌기 상태·열린 입력칸이 탭을 오가도 날아가지 않게 하고, 서버 렌더 구조를 바꾸지 않기 위해서다. 이동 시간은 지금처럼 "화면에 0.5초 머문 날만" 묻는다. 감춘 날은 보이지 않으므로 묻지 않는다(지도 N일차 탭과 결과를 함께 쓰는 것도 그대로).
- 일정의 날짜를 고쳐 다른 날로 옮기면 그 줄은 지금 보는 날에서 사라진다. 이때 "N일차로 옮겼어요" 한 줄을 그날 목록 아래에 잠깐 보인다(Claude 제안, 문구는 빌더).
- 날짜 고르기 줄은 스크롤해도 화면 위에 붙어 있다(sticky, Claude 제안: 일정이 지도·예산·가 볼 곳 아래에 있어 내려간 뒤에도 날을 바꿀 수 있게). 붙은 줄의 바탕은 `background`, 아래 구분선 `rule`.

### 5.5 예산 카드 (`budget-card.tsx`, `budget-forms.tsx`, `money-fields.tsx`)

A(탑승권) 모양: `surface` 카드 하나.

**지금 보이는 숫자는 하나도 빼지 않는다**(Claude 판단: #14 리뷰를 거쳐 정한 정보다). A 모양은 카드 **머리**를 더하는 것이고, 지금의 줄들은 머리 아래에 작은 글자로 남는다.

- **머리(두 탭 공통)**: 여행 전체 "예상 총지출 / 총 예산"(예: "472,000 / 600,000원")과 막대, 그 옆이나 아래에 지금의 여유·초과 문구(`budget-card.tsx` 의 기존 문구 "초과"·"딱 맞아요"·여유 그대로, 초과는 `danger`, 여유는 `ok`).
- **[N일차] 탭**: 머리 위에 "N일차" 한 줄 제목, 머리 아래에 지금의 그날 줄(`PeriodLine`: 그날 예상·실제·차이, 현지 통화 합계와 환산)과 일정 밖 지출 목록 그대로. 시안의 "N일차 예상 지출 162,000원" 은 이 그날 줄을 보기 좋게 다듬은 것이다.
- **[전체] 탭**: 머리 아래에 지금의 요약 줄(`Summary`: 실제 적은 것, 예상과의 차이, 계획에 없던 지출, 남은 예상, 계획 합계)과 날짜별 표·여행 전체 항목·기간 밖 항목·설정 버튼 그대로. 날짜별 표의 날짜 이름 앞에 작은 노선 색 점.
- 예산이 없을 때 [N일차] 탭에는 지금처럼 카드가 없다.
- 막대: 잉크색 채움, 채움 비율 = 예상 총지출 ÷ 총 예산(100% 상한). 넘으면 막대 전체 `danger`.
- 예산이 없을 때: 빈 상태 판("예산을 정하면 …" + [예산 정하기]).
- 숫자는 지금처럼 서버가 계산한 값(`src/lib/budget.ts`)을 그대로 쓴다. 표시만 바뀐다. PR #50 남은 지적 중 화면 문제("예상 0원뿐인 날의 —")는 이번에 함께 본다(빌더 판단).

### 5.6 날짜(노선) 색

- `lineColor(dayNumber)` = `line-((dayNumber - 1) % 8 + 1)`. 9일차부터 1일차 색으로 다시 돈다. 같은 색은 동그라미 안 숫자로 구별한다.
- 노선 색은 **날짜 표시에만** 쓴다: 날짜 동그라미, 일정 노선·역, 이동 줄 글자, 지도 선·핀, 목록의 짧은 노선, 예산 표의 점. 버튼·링크·초점 링·입력칸에는 쓰지 않는다.
- Tailwind 는 동적 클래스 이름을 못 찾으므로 8개 클래스를 배열로 적어 두거나 `style={{ "--line": "var(--color-line-3)" }}` 로 CSS 변수를 넘긴다(빌더 판단). 지도(`@vis.gl/react-google-maps` Polyline `strokeColor`)에는 CSS 변수 대신 실제 색 값이 필요하다: 밝게·어둡게 hex 표를 TS 상수로도 두고, 다크 모드 판별은 `matchMedia` 또는 지도는 밝은 색 하나로 고정(빌더 판단, 지도는 `ColorScheme.FOLLOW_SYSTEM`).

### 5.7 남길 것·지킬 것

- 접근성: 버튼 이름·`aria-pressed`·`role="alert"`·끌기 안내 문구는 그대로. 키보드 초점은 잉크색 2px 링으로 늘 보이게.
- 움직임: 새 애니메이션은 넣지 않는다(끄는 중 떠오름 같은 기존 것만).
- 문구: 바꾸지 않는다. 새로 생기는 문구("N일 남음", "여행 중", "시각 없음")만 한국어로 더한다. 예산 여유·초과 문구는 기존 것을 쓴다.
- 테스트: 순수 함수(`lineColor`, "N일 남음")는 `src/lib/*.test.mjs` 로 시험한다.
